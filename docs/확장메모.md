# 골목 레이더 확장 메모

기록일: 2026-10-29
이 문서는 **MVP에 넣지 않기로 한 아이디어**를 모아둔 곳이다. MVP 개발 중에는 이 목록의 기능을 구현하지 않는다. MVP 완성 후 우선순위를 다시 정하거나, 발표·면접에서 "향후 발전 방향"으로 설명할 때 쓴다.

각 항목의 "선행 조건"이 충족되기 전에는 착수하지 않는다. "주의"는 검증 원칙(`docs/프로젝트_결정사항_v2.md` 6장)과 부딪힐 수 있는 지점이다.

### 1-3. 시간 축 확장

- **전년 동기 비교 / 분기 추세**: 같은 공간 단위·코드 버전의 과거 분기를 확보한 경우에만. 2024년 공간 단위 변경 전후 데이터는 섞지 않는다.
- **상권 변화 신호**: 서울시 상권분석서비스의 상권변화지표(확장·정체·축소 등) 데이터 검토. 원천 정의를 그대로 쓰고 자체 해석을 덧붙이지 않는다.

## 3. 기능 확장

### 3-1. 사용 흐름 강화

- **회원가입·로그인**: 관심 상권·메모를 여러 기기에서 이어 보기. Supabase Auth 검토.
- **비교 리포트 내보내기**: 출처·기준분기·확인 날짜가 붙은 PDF 또는 공유 링크.
- **동업자·상담자 공유**: 비공개 리포트를 특정 사람에게만 공유.
- **현장 사진 첨부**: 체크리스트 항목별 사진. 개인정보(사람 얼굴, 간판 외 정보) 처리 규칙 필요.
- **방문 기록 타임라인**: 같은 상권을 여러 번 방문한 기록을 시간순으로.

### 3-2. 재미·바이럴 요소 (사장님 궁합에서 가져올 수 있는 것)

- **"이 상권에 카페가 몇 개일까?" 맞히기**: 비교 화면 진입 전 퀴즈. 정답은 원천값 그대로.
- **A 상권 vs B 상권 대결 카드**: 공유용 이미지. 승패 판정이나 등급 없이 지표를 나란히 보여주는 형태.
- 주의: 등급·점수·"망할 확률" 같은 단정 표현은 넣지 않는다.

### 3-3. AI 활용

- **현장 체크리스트 문장 다듬기**: 코드가 고른 질문 항목을 자연스러운 문장으로만 바꾸기.
- **비교 결과 요약 문장**: 이미 계산된 숫자를 받아 설명 문장만 생성. 숫자·순위·판정은 AI가 만들지 않는다.
- **메모 정리**: 사용자가 남긴 현장 메모를 항목별로 정리.
- 주의: AI 출력에 숫자가 있으면 원천 계산값과 일치하는지 코드로 검사. API 키는 백엔드 `.env`에만.

### 3-4. 데이터 운영 자동화 (디지털/IT 어필 포인트)

- **갱신 파이프라인**: 새 분기 데이터가 올라오면 수집 → 스키마 검사 → 적재 → 검증 리포트까지 스크립트 한 번으로.
- **데이터 품질 검사 자동화**: 중복 키, 결측, 범위 이탈, 집계 합 불일치를 매 적재마다 검사하고 결과를 기록.
- **버전 관리**: 원천 파일·수집일·기준분기·코드 버전별로 스냅샷 보관. 갱신 실패 시 마지막 정상 버전 사용 + 지연 표시.
- **스케줄 실행**: GitHub Actions 등으로 주기 실행 (클라우드 수업 이후 검토).

### 3-5. 배포·인프라

- 클라우드 수업 이후 실제 배포 (프론트·백엔드·Supabase 운영 프로젝트 분리).
- 카카오맵 사이트 도메인에 배포 주소 등록.
- 사용량·오류 모니터링.

## 4. 사업·직무 연결 확장 (아이디어 수준)

이 항목들은 검증하지 않은 가설이다. 발표에서 언급할 때도 "가능성"으로만 표현한다.

- **소상공인 정책자금·창업 지원 안내**: 비교 결과와 함께 공공기관의 창업 지원 제도 안내 링크를 보여주기. 특정 상품 추천·대출 자동 연결은 하지 않는다.
- **창업 상담 실무자용 작업공간**: 여러 고객의 후보 상권 비교를 관리 (사업기획 v2의 후속 고객 가설).
- **단건 조사 리포트 유료화**: 사업기획 v2의 수익 가설. 실제 수요·지불의사 검증 전에는 매출로 기록하지 않는다.
- **금융기관 관점 연결**: "데이터 근거를 남기고 사후에 검증하는 구조"를 여신 심사·사후관리 프로세스와 비교해 설명 (면접용 서사).

## 5. 우선순위 메모 (MVP 완성 후 다시 정하기)

> **2026-11-10 반영:** 아래 1~4순위와 배포(3-5)는 `docs/plan.md`의 Phase 38~46으로 옮겨 계획을 세웠습니다. 데이터 품질 검사는 Phase 39, 리포트 내보내기는 42, 시간대별 매출 비중은 41, 퀴즈·대결 카드는 44, 배포는 45~46입니다. 회원가입·로그인(3-1)은 Phase 22A·25에서 이미 구현했습니다. 동업자·상담자 공유, AI 활용, 자동 스케줄 실행은 이번 계획에 넣지 않았습니다.

MVP 이후 가장 먼저 검토할 후보:
1. 데이터 품질 검사 자동화 (3-4) — 디지털/IT 직무 어필이 가장 크고, MVP 검증 코드를 확장하면 됨
2. 비교 리포트 내보내기 (3-1) — 사용 흐름 완성도
3. 시간대별 매출 비중 (1-1) — 이미 있는 데이터로 바로 추가 가능
4. 맞히기 퀴즈·대결 카드 (3-2) — 발표 시연의 재미

새 아이디어가 생기면 해당 장에 한 줄씩 추가하고, MVP 범위에는 넣지 않는다.
