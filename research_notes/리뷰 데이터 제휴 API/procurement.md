# 경쟁점 리뷰 데이터 제휴 API 조달·계약 실사

기준일: 2026-10-31  
대상: 서울 카페의 내 가게 및 주변 경쟁점 리뷰를 정식 제휴 API로 수집·분석하는 한국 스타트업 프로토타입  
전제: 화면 스크래핑, 비공개 엔드포인트, 이용약관을 우회하는 수집은 후보에서 제외한다. 아래 내용은 제품·기술·계약 실사를 위한 체크리스트이며 법률 자문이 아니다.

## 1. 계약서에 어떤 데이터 이용 권리를 명시해야 하는가

### Takeaway

공급사가 “API 접근권”만 준다고 해서 골목 레이더가 리뷰를 저장하고 AI로 분석하거나 경쟁점 리포트에 인용할 수 있는 것은 아니다. 계약 본문 또는 권리표에 데이터 원천별로 다음 행위를 각각 허용한다고 명시해야 한다.

1. 리뷰 본문·별점·작성시각·작성자 표시·원문 링크·장소 메타데이터의 API 접근
2. 서버 저장, 캐시, 백업, 인덱싱과 허용 보존기간
3. 감성·주제·키워드·빈도·요약·비교 지표를 계산하는 자동 분석
4. 원문에서 파생된 통계·벡터·라벨·요약을 만들고 상업 서비스에 표시하는 권리
5. 사용자에게 필요한 범위의 원문/발췌문, 별점, 작성자 표시, 원문 링크를 보여주는 권리
6. 내 가게와 주변 동종 업종 경쟁점을 묶어 비교하는 권리
7. 외부 AI/LLM, 번역, 분석, 호스팅 업체를 하위처리자 또는 하도급자로 사용하는 권리
8. 계약 종료, 원천 삭제, 작성자 삭제 요청 때 원문·캐시·파생물·백업을 처리하는 규칙

각 권리는 원천 플랫폼, 국가, 제품, 사용자 수, 호출량, 데이터 종류, 사용 화면, 계약기간과 종료 후 처리까지 한정해 두어야 한다. 공급사가 원천 플랫폼 또는 권리자로부터 이 권리를 재허락할 권한이 있음을 보증하고, 원천 약관 변경이나 권리 상실을 즉시 알리는 의무도 필요하다.

### Cited Findings

- 한국 저작권법은 저작자에게 복제권, 공중송신권, 2차적저작물작성권을 각각 부여한다. 따라서 리뷰가 저작물에 해당하는지와 별개로, 원문 저장·화면 표시·변형적 분석은 계약에서 서로 다른 이용 행위로 나눠 확인하는 것이 안전하다. [국가법령정보센터, 저작권법 제16·18·22조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025203483)
- 한국저작권위원회는 기사 등 언어로 표현된 창작물의 저작권은 저작자에게 있으며, 허락 없는 요약·번역 게시가 복제권·공중송신권·2차적저작물작성권과 관련될 수 있다고 설명한다. 반면 사실·아이디어만 이용하거나 매우 추상적으로 요약한 결과가 독립 저작물이 되는지는 구체적 사안에 따라 달라질 수 있다. [한국저작권위원회 FAQ](https://www.copyright.or.kr/customer-center/faq/list.do?categorycode1=&pageIndex=8&portalcode=&searchkeyword=)
- Google Maps Platform 약관은 별도 허용이 없는 한 콘텐츠의 사전 수집, 인덱싱, 저장, 재공유·재호스팅, 대량 다운로드 및 사용자 리뷰 복사를 금지하고, 콘텐츠를 이용해 새로운 콘텐츠를 만드는 행위도 제한한다. 이는 공급사가 단순히 공개 화면이나 일반 API에 접근할 수 있다는 사실만으로 골목 레이더의 분석·보관 권리를 재허락할 수 없음을 보여주는 대표적 상위약관 사례다. [Google Maps Platform Terms](https://cloud.google.com/maps-platform/terms)
- Google Places 정책은 리뷰 표시 시 작성자 귀속 표시를 요구하고, 개별 리뷰마다 `googleMapsUri`를 이용해 원문에 직접 접근할 수 있게 해야 하며, 리뷰의 정렬·필터 방식도 설명하도록 요구한다. [Google Places API 정책](https://developers.google.com/maps/documentation/places/web-service/policies?hl=en)
- Places API의 리뷰 객체는 원문/현지화 본문, 별점, 작성자 정보, 게시 시각, 신고 링크, 원문 링크를 별도 필드로 제공한다. 조달 시에도 이 수준의 필드와 출처 추적성을 기준으로 삼을 수 있다. [Google Places API Review 스키마](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)

### Inferences

- **Inference:** 계약의 “analytics” 또는 “derived data” 한 문장만으로는 부족하다. `원문을 모델 입력으로 전송`, `임베딩 생성`, `요약 생성`, `집계 지표 영구 보관`, `원문 삭제 후 비식별 집계 유지`를 별도 행위로 열거해야 분쟁 시 범위를 확인하기 쉽다.
- **Inference:** 공급사가 상위 플랫폼 약관이나 리뷰 작성자로부터 필요한 권리를 확보하지 못했다면 “정식 유료 API”라도 사용할 수 없다. 공급사의 수집 방법, 원천 계약 체인, 재허락 범위를 서면으로 받아야 한다.
- **Inference:** 결과 화면은 원문 전체보다 요약·집계 중심으로 설계하고, 원문 발췌는 계약이 허용하는 길이와 귀속·원문 링크 요건을 지키는 편이 제품 가치와 권리 위험을 함께 관리하기 쉽다.
- **Inference:** 공급사 보증에는 제3자 권리 침해와 원천 약관 위반에 대한 방어·배상 범위를 포함하되, 스타트업이 감당할 수 있는 책임상한과 예외를 변호사와 협상해야 한다.

### Gaps

- **법률 검토 필수:** 개별 리뷰가 저작물인지, 감성/주제/요약/임베딩이 2차적저작물 또는 별도 산출물인지, 짧은 발췌가 어떤 조건에서 허용되는지는 일률적으로 단정할 수 없다.
- **법률 검토 필수:** 공급사의 원천 계약과 플랫폼 약관을 실제로 열람해 재허락 권한, 상업 이용, 경쟁 분석, 원문 표시 및 AI 처리 허용 범위를 확인해야 한다.
- 후보 공급사의 이름과 실제 데이터 출처가 아직 정해지지 않아 원천별 금지사항과 필수 귀속 문구는 확정할 수 없다.

## 2. 한국의 개인정보·저작권·플랫폼 약관 위험은 무엇인가

### Takeaway

리뷰의 닉네임, 프로필 사진·URL, 위치·방문 시점, 자유서술 본문은 특정 개인과 연결될 가능성이 있다. 공개된 리뷰라고 해서 개인정보·저작권·플랫폼 약관 검토가 면제되는 것으로 가정하면 안 된다. 최소 수집, 목적 제한, 보존기간, 삭제 전파, 접근통제, 국외이전, 하위처리자, 침해사고 통지와 이용자 고지를 공급사와 골목 레이더 양쪽에서 설계해야 한다.

### Cited Findings

- 개인정보 보호법 제26조는 개인정보 처리업무를 위탁할 때 목적 외 처리 금지와 기술적·관리적 보호조치 등 안전관리에 관한 사항을 문서에 포함하고, 위탁업무와 수탁자(재수탁자 포함)를 공개하도록 규정한다. [국가법령정보센터, 개인정보 보호법 제26조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335321)
- 개인정보 보호법 제28조의8은 개인정보 국외 이전 시 이전받는 자, 목적, 보유·이용기간, 거부 방법과 효과 등의 고지·동의 요건과 보호조치를 두고, 법을 위반하는 내용의 국외이전 계약을 체결할 수 없도록 한다. [국가법령정보센터, 개인정보 보호법](https://www.law.go.kr/lsInfoP.do?lsiSeq=283839)
- 개인정보 보호법 제29조는 내부 관리계획, 접속기록 보관 등 기술적·관리적·물리적 안전조치를 요구한다. [국가법령정보센터, 개인정보 보호법 제29조가 포함된 현행법](https://www.law.go.kr/LSW/lsInfoP.do?ancNo=21445&ancYd=20260310&ancYnChk=0&chrClsCd=010202&efGubun=Y&efYd=20270701&lsiSeq=283839&nwJoYnInfo=N)
- 개인정보보호위원회는 공개된 인터넷 데이터도 적법성과 안전성을 갖춰 처리해야 한다는 취지의 생성형 AI 개발·서비스용 공개 개인정보 처리 안내서를 발표했다. [개인정보보호위원회, 2024 공개 개인정보 처리 안내서](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=10362)
- 개인정보보호위원회의 2026 개인정보 처리방침 작성지침은 처리 목적과 처리 방법을 정보주체가 이해할 수 있도록 투명하게 설명하는 데 중점을 둔다. [개인정보보호위원회, 2026 처리방침 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&nttId=12021)
- 개인정보의 안전성 확보조치 기준은 접근권한, 접근통제, 암호화, 접속기록, 악성프로그램 방지 등의 구체적 보호조치 근거를 제공한다. [국가법령정보센터, 개인정보의 안전성 확보조치 기준](https://www.law.go.kr/admRulLsInfoP.do?admRulSeq=2100000229672&vSct=%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EC%9D%98+%EC%95%88%EC%A0%84%EC%84%B1+%ED%99%95%EB%B3%B4%EC%A1%B0%EC%B9%98+%EA%B8%B0%EC%A4%80)
- 개인정보보호위원회 표준 위탁계약서 예시는 목적 외 처리 금지, 재위탁 제한, 계약 종료 후 개인정보 파기 등을 계약 조항으로 둔다. [표준 개인정보처리위탁 계약서(안)](https://law.go.kr/LSW/flDownload.do?bylClsCd=200203&flNm=%5B%EB%B3%84%EC%A7%80+13%5D+%ED%91%9C%EC%A4%80+%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EC%B2%98%EB%A6%AC%EC%9C%84%ED%83%81+%EA%B3%84%EC%95%BD%EC%84%9C%28%EC%95%88%29&flSeq=145147793)
- Google의 대표적 상위약관은 리뷰 복사·저장·재공유와 콘텐츠 기반 새 콘텐츠 생성을 제한하고, Places 정책은 작성자 표시와 원문 링크를 요구한다. 따라서 플랫폼 약관 준수는 별도의 계약 실사 항목이다. [Google Maps Platform Terms](https://cloud.google.com/maps-platform/terms), [Google Places API 정책](https://developers.google.com/maps/documentation/places/web-service/policies?hl=en)

### Inferences

- **Inference:** 리뷰 작성자 닉네임·프로필·본문을 저장하는 경우 공급사와 골목 레이더 중 누가 개인정보처리자이고 누가 수탁자인지 데이터 흐름별로 정해야 한다. 공급사의 분류를 그대로 따르지 말고 국내 변호사 또는 개인정보 전문가가 판단해야 한다.
- **Inference:** 분석에 작성자 식별자가 필요 없다면 수집 단계에서 작성자 이름·사진·프로필 URL을 제외하거나 별도 암호화 저장하고, UI에서 원문을 보여줄 때만 계약상 필수 귀속정보를 조회하는 구조가 최소수집에 유리하다.
- **Inference:** 외부 LLM API에 리뷰 본문을 보내는 경우 해당 업체가 학습에 사용하지 않는 설정, 저장기간, 처리지역, 하위처리자, 삭제 방법, 침해사고 통지시간을 계약과 기술 설정 양쪽에서 확인해야 한다.
- **Inference:** 공급사가 원천 삭제 또는 작성자 삭제를 통지하면 골목 레이더의 원문, 검색 인덱스, 캐시, 임베딩, 요약, 백업에도 삭제가 전파되도록 `deleted_at`/tombstone 또는 삭제 webhook이 필요하다.

### Gaps

- **법률 검토 필수:** 공개 리뷰의 닉네임·프로필·본문이 구체적 데이터 흐름에서 개인정보에 해당하는지, 골목 레이더의 적법 처리 근거가 무엇인지, 개인정보 처리방침에 무엇을 고지해야 하는지 확인해야 한다.
- **법률 검토 필수:** 국외 클라우드·LLM·분석업체를 쓸 때 제28조의8상 국외이전 근거와 고지·동의 또는 예외 요건을 확정해야 한다.
- **법률 검토 필수:** 원문 발췌, 요약, 리뷰 간 비교가 저작권법상 허용되는 범위와 원저작자 표시·동일성유지권 이슈를 검토해야 한다.
- 실제 공급사의 DPA, 하위처리자 목록, 데이터 위치, 침해사고 절차를 받기 전에는 개인정보 적합성을 통과시킬 수 없다.

## 3. 공급사가 답해야 할 제품·API·데이터 품질 질문은 무엇인가

### Takeaway

POC 전에 실제 서울 카페 샘플로 `장소 선택 → 동종 업종 경쟁점 탐색 → 리뷰 증분 수집 → 출처 확인 → 삭제 반영 → 리포트 생성`을 끝까지 검증해야 한다. API 문서만 보고 구매하지 말고, 아래 필드와 동작을 응답 샘플·샌드박스·계약 SLA로 확인한다.

### Cited Findings

- Google Places의 공식 리뷰 객체는 재조회 가능한 리뷰 리소스명, 현지화/원문 텍스트와 언어, 별점, 작성자 표시, 게시시각, 신고 URL, 개별 원문 URL을 구분해 제공한다. 공급사의 최소 스키마를 비교할 때 참고 가능한 기준이다. [Google Places API Review 스키마](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)

## 5. 공급사 통과/탈락 기준은 무엇인가

### Takeaway

먼저 권리·수집방식·개인정보·삭제·출처 추적의 하드 게이트를 적용하고, 이를 모두 통과한 후보만 품질·운영·가격을 점수화한다. 높은 커버리지나 낮은 가격으로 권리 결함을 상쇄하지 않는다.

### Cited Findings

## 6. 공급사에 보낼 한국어 문의/RFP는 어떻게 작성하는가

### Takeaway

첫 문의부터 “공식 제휴 방식만 검토하며, 경쟁점 리뷰의 분석·파생지표·제한적 표시 권리가 필요하다”는 점을 명확히 해야 한다. 아래 문안은 영업 문의와 1차 실사를 한 번에 진행하기 위한 간결한 초안이다.

### Cited Findings

- 상위 플랫폼에 따라 리뷰 보관·파생·표시와 귀속 조건이 서로 다르므로, 공급사의 자체 약관만이 아니라 원천별 재허락 범위를 확인해야 한다. [Google Maps Platform Terms](https://cloud.google.com/maps-platform/terms), [Google Places API 정책](https://developers.google.com/maps/documentation/places/web-service/policies?hl=en)
- 위탁·국외이전·안전조치가 관련될 수 있으므로 DPA, 처리지역, 하위처리자와 보안 증거를 계약 전에 받아야 한다. [개인정보 보호법 제26조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335321), [제28조의8](https://www.law.go.kr/lsInfoP.do?lsiSeq=283839), [제29조가 포함된 현행법](https://www.law.go.kr/LSW/lsInfoP.do?ancNo=21445&ancYd=20260310&ancYnChk=0&chrClsCd=010202&efGubun=Y&efYd=20270701&lsiSeq=283839&nwJoYnInfo=N)

### Inferences

#### 판매 문의/RFP 이메일 초안

**제목:** [제휴 문의] 서울 카페 경쟁점 리뷰 데이터 API 및 분석 이용권

안녕하세요. 서울에서 첫 카페 창업을 준비하는 사용자를 위한 상권 분석 서비스 **골목 레이더**입니다.

사용자가 선택한 내 가게와 주변 동종 업종 점포의 리뷰를 정식 API로 조회하고, 주제·감성·빈도·비교 요약을 제공하는 기능을 검토 중입니다. 화면 스크래핑이나 비공개 엔드포인트는 사용하지 않으며, 상업 서비스에서의 적법한 데이터 이용권을 계약으로 확인하고자 합니다.

아래 자료를 부탁드립니다.

1. 서울 카페 장소·리뷰 커버리지, 원천별 비율, 업데이트 주기와 평균/최대 지연
2. 장소 검색/매칭, 주변 동종 업종 조회, 리뷰·증분·삭제 API 문서와 샘플 응답
3. 리뷰 본문 접근, 서버 저장, 자동 분석/AI 처리, 파생 지표·요약 생성, 제한적 발췌 표시, 작성자 귀속·원문 링크, 상업 이용, 계약 종료 후 처리의 허용 범위
4. 각 원천 플랫폼으로부터 위 권리를 제공·재허락할 권한이 있다는 확인 및 필수 표시/보존 조건
5. rate limit, pagination, webhook/삭제 통지, 버전·폐기 정책, SLA와 지원 체계
6. DPA, 처리지역, 하위처리자/외부 AI 사용, 고객 데이터의 모델 학습 여부, 보안 인증·침투시험·침해사고 통지 정책

가능하다면 비밀값과 실제 개인정보를 제거한 API 문서, 계약/라이선스 요약, 서울 카페 샘플 데이터로 30분 미팅을 요청드립니다. 회신 자료는 내부 제품·보안 검토와 외부 법률 검토에 사용됩니다.

### Gaps

- 실제 발신자명, 법인명, 연락처와 예상 트래픽을 넣어야 한다.

## 7. 권고 조달 순서와 중단 조건은 무엇인가

### Takeaway

가장 빠른 안전 경로는 `요구사항 고정 → 공급사 권리·보안 서면실사 → 샘플 POC → 법률/보안 승인 → 제한 운영` 순서다. 권리 증명이 없는 상태에서 먼저 개발하거나 실데이터를 적재하지 않는다.

### Cited Findings

- NIST SP 1326은 공급자 실사에서 출처, 소유·지배, 회복탄력성, 기초 보안과 공급망 계층을 구매 전에 평가하도록 안내한다. [NIST SP 1326](https://csrc.nist.gov/pubs/sp/1326/final)
- OWASP는 제3자 API를 안전하지 않게 소비하는 것을 API 보안의 주요 위험으로 분류한다. [OWASP API Security Top 10 2023](https://api-security.owasp.org/editions/2023/en/0x11-t10/)

### Inferences

1. **요구사항 고정:** 경쟁점 정의, 리뷰 기간, 최소 리뷰 수, 화면에 보여줄 원문 범위, 갱신주기, 월 예산 상한을 정한다.
2. **시장 탐색:** 공식 파트너/데이터 라이선서만 대상으로 위 RFP를 보내고, 스크래핑·비공개 API 후보는 즉시 제외한다.
3. **서면 하드 게이트:** 원천 권리 체인, 데이터 사용권, DPA, 하위처리자, 삭제 방식, API 보안을 먼저 검토한다.
4. **샌드박스 POC:** 실제 개인정보를 최소화한 서울 카페 샘플로 장소 매칭, 경쟁점 검색, 리뷰 증분/수정/삭제, 한국어 리포트까지 검증한다.
5. **법률·보안 승인:** 변호사가 계약/권리/개인정보를, 보안 담당이 데이터 흐름·키 관리·DPA 증거를 승인한다.
6. **제한 운영:** 적은 장소·짧은 보존기간·낮은 호출 상한으로 시작하고 누락·매칭오류·삭제지연·비용을 관찰한다.
7. **확대 판단:** SLA와 품질 기준을 연속 충족하고 권리/약관 변경이 없는 경우에만 서울 전체로 확대한다.

즉시 중단 조건:

- **Inference:** 공급사가 화면 스크래핑, 로그인 세션 재사용, 비공개/역공학 엔드포인트를 사용한다.
- **Inference:** 원천별 재허락 권한, 상업 분석권, 파생지표·표시권을 서면 보증하지 않는다.
- **Inference:** 작성자/원천 삭제를 골목 레이더에 전파할 수 없거나, 요청받은 원문을 삭제할 수 없다.
- **Inference:** 하위처리자·처리지역·외부 AI 학습 사용을 공개하지 않는다.
- **Inference:** 장소/리뷰 출처를 검증할 ID·원문 링크·시각 정보가 없다.
- **Inference:** API 키를 프론트엔드에 넣어야 하거나 키 회전·접근통제·사고 통지가 불가능하다.

### Gaps

- 공급사 쇼트리스트와 담당자 연락처가 없다.
- 외부 법률 검토 예산과 승인 담당자가 정해지지 않았다.
- POC 정답셋, 품질 합격선, 호출량·비용 알람 기준은 제품팀이 확정해야 한다.
