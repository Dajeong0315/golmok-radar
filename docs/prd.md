# 골목 레이더 PRD

> 범위 구분: 소개형 홈·마이페이지 요구는 이 문서 11절, 완료된 구현은 plan.md Phase 23~28, 저장·만료·계정 이관 계약은 spec.md 12절에 기록합니다. 아래 최초 MVP의 영구 로컬 저장·첫 화면 정책은 확장 범위에서 대체했습니다. 완료된 전체 업종 요구는 이 문서 12절에 둡니다.

> 이 문서는 상권 탐색·비교 프로토타입 요구사항입니다. “오프라인 창업 첫 파이프라인”, 서울 전역 확장, 매물 검증 워크시트는 `docs/product_v2_pipeline.md`와 `docs/plan.md`의 V2 Phase에서 추적합니다. Phase 19 워크시트는 별도 기능이므로 이 PRD의 기존 상권 비교 흐름과 API·계산 계약을 변경하지 않습니다.

## 1. 문서 목적

이 문서는 골목 레이더 1차 프로토타입에서 누가 무엇을, 왜 사용할 수 있어야 하는지 정리한 제작 요구사항입니다.

상세한 데이터 컬럼, API 형식, 화면 컴포넌트, 데이터베이스 구조와 테스트 조건은 다음 문서인 `docs/spec.md`에서 확정합니다.

## 2. 제품 개요

### 2.1 한 줄 정의

골목 레이더는 예비 카페 창업자가 서울 25개 자치구의 공식 상권을 지도와 목록에서 관심 목록에 모으고, 그중 최대 네 곳을 같은 기준분기로 비교하며 각 숫자의 출처와 계산 근거를 확인할 수 있는 반응형 웹 서비스입니다.

### 2.2 해결하려는 문제

예비 창업자는 상권 통계를 찾을 수 있어도 다음 문제를 겪습니다.

- 서로 다른 기준시점의 숫자를 비교하기 쉽습니다.
- 숫자의 출처, 공간 단위, 업종 코드, 계산 방법을 확인하기 어렵습니다.
- 통계만 보고 실제 창업 성과를 단정하기 쉽습니다.

골목 레이더는 동일 기준분기와 동일 상권·업종 코드를 사용하고, 수치의 근거를 함께 제시해 사용자가 직접 판단할 수 있도록 돕습니다.

## 3. 사용자

### 주 사용자

서울에서 첫 카페 창업을 준비하며, 여러 후보를 모아 두고 2~4곳씩 비교하려는 예비창업자입니다. 가게 운영 경험이 없어도 이해할 수 있는 쉬운 설명을 기본으로 합니다.

### 사용 환경

- PC 브라우저: 후보 상권과 지표를 자세히 비교
- 휴대폰 브라우저: 후보 상권을 찾아보고 현장 확인 질문을 참고

회원가입이나 로그인 없이 사용할 수 있어야 합니다.

## 4. 핵심 사용자 흐름

1. 사용자가 상권 목록 또는 지도 화면을 엽니다.
2. 서울 25개 자치구의 공식 상권을 탐색합니다.
3. 원하는 상권을 관심 목록에 저장합니다.
4. 관심 목록에서 비교할 상권 2~4곳을 선택합니다.
5. 서비스는 같은 기준분기 데이터를 사용해 지표를 나란히 보여 줍니다.
6. 사용자는 필요한 지표에서 근거 보기를 열어 출처·원천값·계산식을 확인합니다.
7. 사용자는 현장 확인 질문을 참고해 통계로 판단하기 어려운 내용을 직접 확인합니다.

## 5. 기능 요구사항

### 5.1 상권 목록·지도와 관심 목록

서비스는 다음 조건의 상권을 보여 줍니다.

- 대상 지역은 서울 25개 자치구입니다.
- 대상 업종은 카페이며 원천 업종 코드는 `CS100010`(커피-음료)입니다.
- 서울시 영역 데이터에 존재하는 공식 상권 1,650곳을 탐색 대상으로 제공합니다.
- 각 상권에는 상권명, 자치구, 상권 코드, 상권 구분을 표시합니다.
- 목록과 지도는 같은 상권 정보를 가리켜야 합니다.

사용자는 목록 또는 지도에서 원하는 상권을 관심 목록에 추가하거나 제거할 수 있어야 합니다. 관심 목록은 로그인 없이 브라우저 로컬 저장소에 보관합니다. 사용자는 저장한 상권 중 서로 다른 2~4곳을 비교 대상으로 선택할 수 있어야 하며, 다섯 번째 상권을 선택하려 하면 최대 네 곳이라는 안내를 표시합니다.

### 5.2 2~4개 상권 비교

서비스는 선택한 2~4개 상권을 같은 기준분기로 비교합니다.

- 초기 기준분기는 2025년 4분기(`20254`)입니다.
- 선택한 모든 상권 이름과 기준분기를 비교 화면에서 항상 확인할 수 있어야 합니다.
- 비교 가능한 지표와 비교 불가 지표를 구분해 표시합니다.
- 비교 불가 값은 0, 빈 값, 임의의 추정값으로 바꾸지 않습니다.

1차 비교 지표는 다음과 같습니다.

| 구분 | 지표 | 요구사항 |
| --- | --- | --- |
| 필수 | 카페 점포 수 | 선택한 상권·분기·업종의 원천값을 표시합니다. |
| 필수 | 개업률·폐업률 | 선택한 상권·분기·업종의 원천값을 표시합니다. |
| 필수 | 추정 유동인구 | 인구 데이터의 공간 코드·기준분기 검증 후 표시합니다. |
| 필수 | 카페 추정매출 | 개인·법인 합계 기준의 원천값을 표시합니다. |
| 추가 | 시간대별 유동인구 분포 | 시간대별 인구를 전체 인구로 나눈 결과를 표시합니다. |
| 추가 (Phase 41) | 시간대별 매출 비중 | 선택 업종의 시간대별 추정매출을 전체 추정매출로 나눈 결과를 표시합니다. 유동인구와 같은 6개 시간대를 쓰지만 두 분포를 인과관계로 설명하지 않습니다. |
| 추가 | 주중·주말 매출 비중 | 주말 매출을 전체 매출로 나눈 결과를 표시합니다. |
| 선택 | 건당 평균 결제액 | 매출 금액을 매출 건수로 나눈 결과를 표시합니다. |

### 5.3 숫자의 근거 보기

모든 비교 지표는 사용자가 근거를 확인할 수 있어야 합니다. 근거 보기에는 가능한 범위에서 아래 정보를 표시합니다.

- 제공기관과 데이터셋 이름
- 원천 파일명 또는 Open API 수집 정보
- 수집일과 데이터 기준분기
- 상권 코드·상권명·업종 코드·업종명
- 데이터를 고른 필터 조건
- 원천값
- 계산식, 단위 변환, 반올림 규칙
- 계산에 사용한 원천 행 또는 원천 행을 확인할 방법

원천값만 표시한 지표도 해당 사실을 명시합니다. 계산형 지표는 계산식과 분모가 0이거나 데이터가 없을 때의 처리 기준을 함께 표시합니다.

### 5.4 현장 확인 질문

비교 화면 또는 별도 화면에서 사용자가 현장에서 확인할 질문을 제공합니다.

- 질문은 통계 지표의 한계를 보완하기 위한 참고 정보입니다.
- 서비스는 질문에 대한 정답이나 상권 추천 결과를 제공하지 않습니다.
- 예시는 시간대별 실제 보행 흐름, 카페 경쟁 점포, 공실, 고객 체류 목적 등입니다.

## 6. 데이터 요구사항

### 6.1 사용 데이터

| 용도 | 데이터 |
| --- | --- |
| 점포 수·개업률·폐업률 | 서울시 상권분석서비스(점포-상권) |
| 카페 추정매출·매출 건수·주중/주말 매출 | 서울시 상권분석서비스(추정매출-상권) |
| 유동인구·시간대별 유동인구 | 서울시 상권분석서비스(길단위인구-상권) |
| 상권명·경계·지도 표시 | 서울시 상권분석서비스(영역-상권) |

### 6.2 결합과 검증

- 데이터는 동일한 상권 코드와 동일한 기준분기가 확인된 경우에만 결합합니다.
- 점포·매출 데이터의 카페 업종 코드는 `CS100010`을 사용합니다.
- 인구 데이터도 상권 코드와 기준분기 일치 여부를 수집 후 검증합니다.
- 원천 파일의 컬럼명이 연도별로 달라도, 적재 과정에서 의미가 같은 컬럼을 통일해 처리합니다.
- 데이터 출처와 수집·검증 결과는 `docs/data_sources.md`에 기록합니다.

## 7. 품질 및 표시 원칙

- 숫자·등급·추천 결과를 AI가 임의로 만들지 않습니다.
- 계산형 지표는 엑셀 손계산 기준표와 자동 테스트가 일치할 때만 사용합니다.
- 비교 기준이 다르거나 데이터가 없으면 이유와 함께 비교 불가로 표시합니다.
- 화면은 PC와 모바일에서 주요 흐름을 사용할 수 있도록 반응형으로 제공합니다.
- API 키, 데이터베이스 비밀번호, 연결 문자열은 코드·문서·Git에 저장하지 않습니다.

## 8. 이번 범위에서 제외하는 기능

- 회원가입·로그인
- 계정 기반 관심 상권 동기화·개인 메모 저장
- 비교 리포트 공유
- 창업 성공 확률, 상권 등급, 자동 추천
- 개별 점포 매출 예측
- 매출 대비 유동인구를 구매전환율로 단정하는 지표
- 전국 단위 확장과 대출 상품 자동 연결

## 9. 완료 판단 기준

다음 조건을 모두 만족하면 1차 프로토타입 요구사항을 충족한 것으로 봅니다.

- 사용자가 지도에서 상권을 관심 목록에 저장하고, 그중 2~4곳을 골라 같은 분기의 지표를 비교할 수 있습니다.
- 수치마다 기준분기와 출처, 필터, 원천값 또는 계산식을 확인할 수 있습니다.
- 결측·미제공·기준 불일치가 0으로 표시되지 않습니다.
- 계산형 지표가 사전에 정한 엑셀 손계산 결과 및 자동 테스트와 일치합니다.
- PC와 휴대폰에서 후보 선택, 비교, 근거 확인 흐름을 사용할 수 있습니다.

## 11. 소개형 홈·마이페이지와 비로그인 이용 (Phase 23~28)


### 소개형 홈

상단 메뉴는 ‘서비스 소개 · 상권 탐색 · 내 기록’ 중심으로 단순화합니다. 로그인 전에는 ‘카카오 로그인’, 로그인 후에는 ‘마이페이지’를 제공합니다. 도구 화면 안에서 성향 테스트·매물 검증·공식 정보로 이동할 수 있게 하되 모든 기능을 홈 상단에 나열하지 않습니다.

홈의 순서:

1. 서비스 한 줄 소개, 대상 사용자, 대표 행동 ‘내 창업 조건 정리하기’, 보조 행동 ‘상권 바로 탐색하기’.
2. 무엇을 확인할 수 있는지 3개 요약: 내 조건, 같은 기준의 상권 비교, 직접 확인할 매물·현장 항목.
3. 기존 사용 흐름을 요약한 ‘조건 정리 → 상권 탐색·비교 → 매물 검증 → 공식 정보 확인’. 기존 운영 개선은 준비 중인 별도 확장으로 짧게 안내하며 작동하지 않는 CTA는 만들지 않음.
4. 실제 결과 예시 1개: 예시 여부·기준분기 명시. 숫자 없는 장식용 성공 점수는 사용하지 않음.
5. 신뢰와 한계: 공식 출처·기준분기·결측 표기, 통계가 성공이나 계약을 판정하지 않는다는 짧은 안내.
6. 기록 저장 안내와 마지막 시작 버튼. 푸터에 개인정보 처리 안내와 문의 경로(실제 운영 경로 준비 후 노출).

전체 지도, 1,650곳 목록, 상세 지표 표, 저장 목록은 홈에서 제외하고 탐색 화면으로 옮깁니다. 홈 첫 화면에서 데이터 API 응답을 기다릴 필요가 없게 합니다.

### 마이페이지

| 영역 | 첫 버전 기능 |
| --- | --- |
| 요약 | 최근 저장 기록, 종류별 개수, 새 테스트·탐색 진입 |
| 테스트 결과 | 날짜·기록 이름·유형 요약, 다시 열기, 이름 변경, 삭제, ‘기존 테스트 결과 보기’ 옆 ‘테스트 다시 해보기’(빈 답변의 새 초안, 기존 결과 보존) |
| 저장 상권 | 공식 상권명·자치구, 개인 별칭 변경(공식명은 함께 유지), 해제, 2~4곳 비교 |
| 리포트 | 유형·제목·생성일·기준분기·업종·대상 상권, 상세 열기, 이름 변경, 삭제 |
| 매물 워크시트 | 기존 기능을 보존하여 목록·열기·수정·이름 변경·삭제, 저장 상태 표시 |
| 계정 관리 | 카카오 연결 표시, 제공된 닉네임/이메일만 표시, 로그아웃, 기록 전체 삭제, 회원 탈퇴 |

빈 목록에는 해당 작업으로 바로 이동할 수 있는 안내를 제공합니다. 목록은 최신순, 유형 필터와 더 보기/페이지 단위 로드를 기본으로 합니다. 복잡한 폴더·태그·전문검색은 후속으로 둡니다. 카카오 비밀번호·이메일 변경 기능은 제공하지 않으며 필요한 경우 카카오 계정 관리로 안내합니다.


### 비로그인 기록과 로그인 전환

- 기본 주소 방문은 소개형 홈으로 안내하되 새 방문만으로 기록을 삭제하지 않습니다. 마지막 실제 활동 후 60분 미활동 시 익명 기록이 만료됩니다. 유효 기간 내 새로고침·재방문은 복구합니다.
- 첫 이용 안내와 상시 작은 안내, 활동 중 20분 간격 알림, 만료 10분·2분 전 예고로 로그인하지 않으면 기록이 사라진다는 사실을 알립니다. 작업을 막는 반복 팝업은 사용하지 않습니다. 세부 중복 억제와 활동 기준은 SPEC을 따릅니다.
- 비로그인 테스트 결과·후보/비교 리포트·관심 상권·매물 워크시트·작성 중 초안을 임시 보관합니다. 로그인 버튼에는 ‘남아 있는 이용 기록을 이 계정에 저장합니다’라는 안내를 제공합니다.
- 로그인하면 아직 만료되지 않은 전체 기록을 해당 계정의 기존 기록에 추가합니다. 기존 기록을 교체하지 않으며 서버 저장 확인 전 임시 기록을 지우지 않습니다. 저장 중·완료·실패/재시도를 표시합니다.
- ‘기존 테스트 결과 보기’와 ‘테스트 다시 해보기’를 테스트 진입부와 마이페이지 테스트 영역에서 나란히 제공합니다. 이전 결과를 지우지 않고 새 테스트를 시작하며 중단해도 이전 결과를 볼 수 있습니다. 기존 답변 수정은 별도 동작으로 구분합니다.
- 로그인한 사용자의 새로운 테스트·리포트는 ‘내 기록에 저장’으로 보관합니다. 로그인 전 기록의 자동 이관은 이 버튼을 다시 누르게 하지 않습니다.
- 추가 필수 기능: 저장 상태·재시도, 저장 날짜/기준분기 구분, 빈 목록 다음 행동, 개별/전체 삭제 구분, 개인정보·삭제 안내. 검색·태그·기록 내보내기는 `plan.md` Phase 43에서 진행하고 폴더 포함 여부는 그 Phase 시작 전에 정합니다. 공개 공유·추천 점수·성공 확률은 추가하지 않습니다.

### Phase 23 적용 현황 (2026-11-03)

소개형 홈과 사용 흐름 통합, 별도 상권 탐색과 단순 메뉴를 구현했습니다. 기본 주소와 #home은 홈, #explore는 탐색입니다. 이전 #top/#explorer-title/#favorites-title은 탐색 호환 경로이며 #workflow는 홈 사용 방법 영역입니다. 홈에서는 지도 SDK와 상권 데이터 조회를 시작하지 않고 정보 구성 예시만 표시합니다. 로고는 홈, 관심 목록·탐색 복귀 링크는 해당 도구로 이동합니다. 이후 Phase 24~28도 완료했으며 검증·제약은 plan.md의 Phase별 실행 기록에 남깁니다.

## 12. 전체 업종 확대와 가게 위치 확인 (Phase 29~33 완료)

- 사용자는 2025년 4분기 공식 점포 원천에 있는 100개 업종을 선택해 25개 자치구 상권을 탐색하고 2~4곳을 같은 업종·분기로 비교합니다. 매출 원천에 없는 38개 업종과 매출 행이 없는 상권은 해당 지표를 `비교 불가`로 표시합니다.
- 업종 선택은 지도·목록·비교·근거·후보 리포트·저장 기록 재열기에서 유지됩니다. 성향 진단의 넓은 업종군은 공식 세부 업종과 구분하여 사용자가 분석할 업종을 선택하게 합니다. 유동인구·임대처럼 업종 공통인 자료를 해당 업종의 고객/매출/임대료로 오해하게 하지 않습니다.
- 리뷰 화면에서 가게 검색 결과를 클릭하면 지도에 그 결과의 위치·주소·분류를 보여 줍니다. 사용자가 위치를 확인한 뒤 상권 판별과 주변 가게 탐색을 시작합니다. PC에서는 결과 옆, 모바일에서는 아래에 지도를 배치합니다.
- 개업 후에는 선택한 내 가게와 같은 세부 업종의 주변 가게를 익명으로 비교하고, 창업 전에는 선택 상권·업종의 공개 리뷰 제한 표본에서 공통 반응을 살펴봅니다. 카카오 장소 분류와 서울시 업종 코드의 대응이 불명확하거나 리뷰가 부족하면 비교·아이디어를 만들지 않고 이유를 표시합니다. 기존 수집량·빈도·비식별화·90일 보관 제한을 유지합니다.
