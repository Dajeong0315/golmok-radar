### 기술 스택

| 영역 | 기술 | 비고 |

| 자동 테스트 | pytest (+ 프론트는 필요 시 Vitest) | 계산식 기대값은 엑셀 손계산과 일치해야 통과 |

| AI 코딩 도구 | Claude Code (`CLAUDE.md`) 또는 Codex (`AGENTS.md`) | 작업 규칙 파일은 프로젝트 루트에 둔다 |

| 테스트 DB | **테스트용 Supabase 프로젝트** | 운영용과 분리된 별도 프로젝트. 연결 정보는 `backend/.env.test` 등 별도 파일에 두고 Git에서 제외. 테스트는 매번 테이블을 비우고 시작 |

## 3. 핵심 사용 흐름 (MVP)

지역·업종 선택 → 상권 목록·지도 탐색 → 관심 상권 저장 → 저장한 상권 중 2~4곳 선택 → 같은 기준분기로 비교 → 숫자마다 근거 보기 → 현장 체크리스트 → (2차) 계정 동기화·메모 저장

### 분석 범위 (2026-10-30 서울 전역 확장)

- 자치구: **서울 25개 자치구**
- 업종: **카페** (서울시 생활밀접업종 중 커피·음료 업종. 정확한 업종코드는 원자료 코드표로 확인)
- 서울 공식 상권 1,650곳을 지도와 목록에서 탐색할 수 있게 한다. 사용자는 원하는 상권을 브라우저 관심 목록에 모으고, 같은 구 안 또는 구를 넘어서 2~4곳을 비교할 수 있다.

### 1차 프로토타입 범위 (10/30~11/2)

- 서울 25개 자치구 공식 상권 · 카페 · 공통 기준분기 1개 · 관심 목록에서 최대 4개 비교
- 비교 지표 (2026-10-29 확정, 원자료 컬럼 확인 후 정의 확정):

| 구분 | 지표 | 정의 | 종류 |
|---|---|---|---|
| 필수 | 카페 점포 수 | 상권 내 카페 점포 수 | 원천값 |
| 필수 | 개업률 / 폐업률 | 해당 분기 개업·폐업 점포 비율 | 원천값 |
| 필수 | 추정 유동인구 | 상권 내 총 유동인구 (`STDR_YYQU_CD` 분기 원천값) | 원천값 |
| 필수 | 카페 추정매출 | 분기 매출 금액 (개인+법인 합계) | 원천값 |
| 추가 | 시간대별 유동인구 분포 | 시간대별 유동인구 ÷ 전체 | 계산 |
| 추가 | 주중 / 주말 매출 비중 | 주말 매출 ÷ 전체 매출 | 계산 |
| 선택 | 건당 평균 결제액 | 매출 금액 ÷ 매출 건수 | 계산 |

  계산형 지표는 모두 엑셀 손계산과 pytest로 대조한다. 위 목록에 없는 지표와 조합 지표(D 그룹)는 MVP에서 제외하고 `docs/확장메모.md`에 기록한다.
- 숫자마다 근거 보기: 출처 기관, 데이터셋, 기준분기, 수집일, 코드 버전, 필터, 계산식, 반올림 규칙, 원천 행 내려받기
- 결측·미제공은 "비교 불가"로 표시
- 회원가입·로그인 없음

### 2차 프로토타입 범위 (11/3~11/4)

- 현장 체크리스트, 계정 기반 관심 상권 동기화·메모 저장, 비교 리포트 공유
- Supabase 이전·연결 확인, 오류 처리 보완
- 여유가 있으면: 데이터 갱신 스크립트 자동화

### 만들지 않는 것

- 등급·점수·창업 성공 확률·개별 점포 매출 예측
- 매출 ÷ 유동인구를 "구매전환율"로 표시하는 것
- 상권 통계를 임의 반경(500m 등)으로 재분배하는 것
- 전국 확대, 대출 상품 자동 연결
- 확장·발전 아이디어는 MVP에 넣지 않고 모두 `docs/확장메모.md`에 남긴다

## 5. 데이터 계획과 go / no-go

### 사용할 데이터 후보

| 용도 | 데이터 | 제공 | 상태 |
|---|---|---|---|
| 추정 유동인구 | 서울시 상권분석서비스(길단위인구-상권) | 서울신용보증재단 / 서울 열린데이터광장 | Open API 36,281건 수집·컬럼 확인 완료 |
| 추정매출 | 서울시 상권분석서비스(추정매출-상권) | 서울신용보증재단 / 서울 열린데이터광장 | 파일 수신·컬럼 확인 전 |
| 점포 수·개폐업 | 서울시 상권분석서비스(점포-상권) | 서울신용보증재단 / 서울 열린데이터광장 | 데이터셋 ID·컬럼 확인 전 |
| 상권 경계·코드 | 서울시 상권 영역 데이터 | 서울 열린데이터광장 | 확인 전 |
| 점포 위치(지도 탐색용) | 소상공인시장진흥공단 상가(상권)정보 | 공공데이터포털 | 대체·보조용 |
| 사용하지 않음 | 서울시 상권분석서비스(소비-상권) | — | 갱신 중단이 명시됨 |

확인된 주의점 (2026-10-29 기준 열린데이터광장 안내)
- 소비 관련 데이터는 행정동보다 작은 상권 단위를 더 이상 갱신하지 않는다고 안내되어 있다.
- 2026년 중 일부 컬럼 삭제, 제공 기간 변경(2021년 이후 자료만 제공) 공지가 있었다.
- 상주인구 데이터는 분기 단위지만 연 1회만 갱신된다.
- 일부 데이터셋 페이지에서 파일 목록이 비어 있었다. Open API 또는 다른 경로로 받아야 할 수 있다.
- 메타데이터 수정일은 최신 관측 분기가 아니다. 실제 사용 가능한 최신 공통 분기는 아직 확인하지 않았다.
- **2024년부터 서울시 상권분석서비스의 공간 단위가 '표준단위구역'으로 바뀌었다.** 결합 키가 기존 상권코드인지, 표준단위구역 코드인지, 두 코드의 대응표가 있는지 파일로 확인해야 한다.
- 길단위인구 Open API는 `STDR_YYQU_CD` 기준 분기 데이터를 제공한다. `20254` 원천 행을 별도 월 집계 없이 사용한다.
- 추정매출의 분기 매출은 개인+법인 합계이고, 법인 매출에는 성별·연령 정보가 없어 성별·연령별 합이 총매출과 다를 수 있다.
- 웹 데이터셋 페이지의 미리보기와 별개로, 길단위인구 API 응답에서 총량·시간대별 컬럼을 확인했다.

### 데이터 확인 체크리스트 (10/29)

1. 서울 25개 자치구 공식 상권 전체의 코드를 확보하고, 대표 검증 상권의 **상권코드(또는 표준단위구역 코드)**를 대조한다.
2. 점포·길단위인구·추정매출 세 데이터에 **같은 상권코드**가 있는지 확인한다.
3. 세 데이터에 **공통 기준분기**가 있는지 확인한다. (예: 세 파일 모두 [YYYY년 N분기] 행 존재)
4. 업종 코드 체계가 점포와 추정매출에서 같은지 확인한다.
5. 각 파일의 제공기관, 수집일, 기준분기, 코드 버전을 `docs/data_sources.md`에 기록한다.

### go / no-go 기준

| 결과 | 진행 |
|---|---|
| 상권 3개 이상에서 세 데이터가 같은 분기로 모두 존재 | **go**: 계획대로 진행 |
| 매출 또는 인구가 일부 상권만 존재 | 범위 축소: 있는 상권만 비교, 없는 칸은 "비교 불가" |
| 상권 단위가 비어 있거나 분기가 맞지 않음 | 행정동 단위로 낮춰서 진행하거나, 과거 공통 분기로 고정하고 화면에 명시 |
| 인구·매출 모두 확보 불가 | 점포 데이터만으로 1차를 완성하고 "소비·유동인구 분석"을 약속하지 않음 |

## 6. 검증 원칙

v1의 검증 기준 7개를 유지하고, 구현 방식을 아래처럼 정한다.

1. 원천 파일, 제공기관, 수집일, 기준분기, 공간·업종 코드 버전을 보관한다.
2. 각 화면 지표에서 원천 값과 필터·계산식을 확인할 수 있게 한다.
3. 같은 공간·기간의 데이터만 결합하고, 인구가 업종별 행에 반복되어도 중복 합산하지 않는다.
4. 표본 지역의 값과 직접 계산 결과를 대조한다. 반올림·단위 변환은 명시한다.
5. 결측·미제공을 0으로 바꾸지 않고 "비교 불가"로 표시한다.
6. 원천 추정치가 실제 현장과 일치한다고 주장하지 않는다. 현장 기록과 통계의 확인 범위를 구분한다.
7. 개별 가게 매출·구매전환율·창업 성공률을 단정하지 않는다.

구현 규칙
- **숫자는 코드가 계산한다.** 등급·점수·금액을 AI가 정하지 않는다.
- **엑셀 손계산 기준표**: 정상 2건, 경계값 2건, 극단·결측 1건 이상을 먼저 엑셀로 계산한다.
- 그 기대값을 pytest에 그대로 넣어, 코드 결과가 엑셀과 다르면 테스트가 실패하게 한다.
- 화면의 "근거 보기" 값과 엑셀 값을 눈으로 대조한다.
- README에 "엑셀 손계산 N건과 일치 확인"을 기록한다.

## 7. 보안 규칙

- API 키, DB 비밀번호, Supabase 연결 문자열은 `backend/.env`에만 둔다. 코드·문서·Git·AI 대화창에 붙여넣지 않는다.
- `.env.example`에는 항목 이름과 설명만 적는다.
- 공개 저장소에 올리기 전 커밋 내용에 비밀값이 없는지 확인한다.
- 수업 노션 페이지에 평문으로 적힌 API 키는 이 프로젝트에 복사하지 않는다.
- 사용자 메모·관심 상권은 기본 비공개로 저장한다.
