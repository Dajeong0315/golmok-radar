# 골목 레이더 V2 — 오프라인 창업 첫 파이프라인

## 1. 제품 컨셉

골목 레이더 V2는 “상권 숫자 비교 도구”를 넘어, 오프라인 창업을 원하는 사람이 막연한 아이디어를 실행 가능한 후보로 좁히는 첫 파이프라인을 제공합니다.

```text
창업 성향 진단
  → 업종·운영 방식 정리
  → 설명 가능한 후보 상권 2~3곳
  → 후보별 강점·약점 리포트
  → 임대 수준·매물 확인
  → 지원 제도·자금 후보 확인
  → 개업 후 내 가게와 주변 경쟁점 리뷰 비교
```

Phase 16에서 서울 공식 상권 1,650곳으로 넓힌 탐색·2~4곳 비교·근거 보기는 이 파이프라인의 **상권 판단 엔진**으로 유지합니다.

## 2. 사용자 단계와 제품 가치

| 단계 | 사용자의 질문 | 제품이 제공하는 것 |
| --- | --- | --- |
| 아이디어 | 나는 어떤 오프라인 사업을 원하는가? | 6문항 창업 성향 진단 |
| 후보 찾기 | 내 조건과 맞는 상권은 어디인가? | 근거가 보이는 후보 2~3곳 |
| 검토 | 각 후보의 장단점은 무엇인가? | 동일 기준 데이터 기반 강점·약점 리포트 |
| 입지 결정 | 실제 임대 수준과 매물은 어떤가? | 공신력 있는 임대 통계, 허가된 매물 연결 |
| 자금 준비 | 신청해 볼 지원과 자금은 무엇인가? | 자격 조건을 설명하는 공식 제도 후보 2건 |
| 운영 개선 | 손님 반응에서 무엇을 바꿔야 하는가? | 내 가게와 주변 동종 가게의 리뷰 주제 비교 |

## 3. 창업 성향 진단

### 3.1 표시 원칙

- 기능명은 “심리 진단”이 아니라 **창업 성향 진단**으로 표시합니다.
- 임상·심리 검사나 성공 가능성 예측이 아니며, 답변은 후보 탐색 기준을 정리하는 데만 사용합니다.
- 로그인 전 답변과 결과는 브라우저에 저장합니다. 서버 저장은 명시적 동의와 계정 기능이 생긴 뒤에만 합니다.
- 결과 화면에서 사용자는 업종·예산·선호를 직접 수정할 수 있어야 합니다.

### 3.2 6개 질문과 선택지

| 번호 | 질문 | 선택지 4개 | 반영 축 |
| --- | --- | --- | --- |
| Q1 | 지금 가장 먼저 열어 보고 싶은 가게는 무엇인가요? | 카페·디저트 / 식당·주점 / 소매·편집숍 / 생활서비스·스튜디오 | 업종 |
| Q2 | 어떤 손님이 자주 찾아오는 가게를 만들고 싶나요? | 동네 단골 / 직장인 / 목적 방문객 / 저녁 손님 | 수요 유형 |
| Q3 | 첫 가게의 비용은 어떤 방식으로 정하고 싶나요? | 작게 시작 / 비용·성장 균형 / 기회에 투자 / 숫자부터 확인 | 위험·예산 |
| Q4 | 문을 연 뒤에는 누가 가게를 운영할 계획인가요? | 1인 / 가족·동업자 / 직원과 팀 / 커뮤니티 중심 | 운영 역량 |
| Q5 | 가게를 준비하면서 가장 즐겁게 할 수 있는 일은 무엇인가요? | 메뉴·상품 / 손님 응대 / 공간·브랜드 / 매출·비용 관리 | 창업자 강점 |
| Q6 | 근처에 비슷한 가게가 많다면 어떻게 느낄 것 같나요? | 경쟁 적은 곳 / 확인된 수요 / 차별화 경쟁 / 유동 우선 | 경쟁 선호 |

### 3.3 결과 유형

답변을 단일 성격 유형으로 단정하지 않고 네 축을 보여 줍니다.

- 업종 관심: 카페·외식·소매·서비스
- 수요 선호: 생활권·업무권·목적방문·야간
- 운영 성향: 소형 효율·균형 운영·확장 운영·관계 중심
- 위험 선호: 보수·균형·성장

결과 예시: `생활권 단골을 만드는 소형 효율형 · 카페/디저트 관심`. 각 축별로 어떤 답변이 반영됐는지 공개합니다.

## 4. 후보 상권 2~3곳 추천

### 4.1 추천이 아니라 설명 가능한 후보 좁히기

화면 문구는 “성공할 상권”이 아닌 **조건이 잘 맞는 탐색 후보**로 표현합니다. 사용자의 업종·운영 조건을 충족하는 상권만 남긴 뒤 아래 데이터로 적합도를 계산합니다.

1. 업종 데이터가 존재하는 상권만 필터링합니다.
2. 사용자의 필수 조건(지역, 업종, 예산 상한)을 먼저 적용합니다.
3. 유동인구 시간대, 주중·주말 매출, 점포 수, 개·폐업률을 각 상권 집단 내 백분위로 변환합니다.
4. 답변 축과 지표의 명시된 가중치를 적용합니다.
5. 같은 이유의 후보만 몰리지 않도록 최대 3곳을 다양화합니다.
6. 점수, 기여 지표, 제외 조건, 데이터 기준분기를 사용자에게 공개합니다.

초기 V2는 현재 검증된 카페 업종만 실제 추천을 제공합니다. 다른 업종을 선택하면 성향 결과는 보여주되, 해당 업종 데이터 검증이 끝날 때까지 추천 대신 “준비 중”과 수동 상권 탐색을 제공합니다.

### 4.2 추천 결과 카드

- 상권명·자치구·상권 유형
- “왜 이 후보인가” 2~3개 근거
- 주의할 점 1~2개
- 기준분기와 데이터 완전성
- 관심 상권 저장, 기존 비교 화면에 추가
- 추천 기준 상세 보기

## 5. 상권별 강점·약점 리포트

리포트는 생성형 AI가 수치를 새로 만들지 않고 검증된 지표의 상대 위치를 문장으로 바꿉니다.

- 강점: 비교 모집단의 상위 30%인 검증 지표
- 약점/주의: 하위 30%이거나 원천 데이터가 누락된 지표
- 중립: 나머지 지표
- 모든 문장은 수치·비교 모집단·기준분기·근거 보기로 연결
- “성공 가능”, “핫플 보장”, “무조건 유리” 같은 표현 금지

예: “주말 매출 비중이 비교 가능한 서울 카페 상권 중 상위 30%입니다. 반면 개업률과 폐업률이 모두 높아 경쟁 변동성을 현장에서 확인해야 합니다.”

## 6. 임대 데이터와 매물

### 6.1 단계별 제공

1. **공식 임대 벤치마크**: 한국부동산원의 상업용부동산 임대동향조사에서 상권별 임대료·공실률·임대가격지수를 분기 단위로 제공합니다.
2. **사용자 입력 예산 시뮬레이터**: 보증금, 월세, 관리비, 면적을 사용자가 입력하면 월 고정비와 매출 대비 부담을 계산합니다.
3. **실매물 연결**: 정식 제휴 또는 재사용이 허용된 매물 API가 확보된 경우에만 매물 목록을 연결합니다.

### 6.2 네이버 부동산 처리 원칙

2026-10-29 확인 기준 NAVER Developers 공개 API 목록에는 부동산 매물 API가 확인되지 않았습니다. 비공개 엔드포인트 호출, 화면 크롤링, 로그인 우회는 구현하지 않습니다. 제휴 API와 재사용 권한이 확인되기 전에는 네이버 부동산으로 이동하는 검색 링크만 제공할 수 있습니다.

공식 임대 통계는 실제 개별 매물 가격이 아니라 분기 표본 통계이므로 화면에서 “실시간 매물”로 표현하지 않습니다.

## 7. 창업 지원·자금 후보 2건

### 7.1 1차 범위

- K-Startup 공식 지원사업 공고 API에서 모집 중인 사업을 수집합니다.
- 업종, 지역, 예비/기창업, 업력, 대표자 연령 등 공개된 자격 조건으로 필터링합니다.
- 조건이 많이 맞는 후보 2건을 보여 주고, 일치·불일치·확인 필요 조건을 각각 표시합니다.
- 신청은 공식 상세 페이지로 이동하며 서비스가 승인 가능성이나 금리를 보장하지 않습니다.
- 진단 결과에는 IBK기업은행·KDB산업은행 공식 안내 중 사업 단계와 자금 용도에 따라 먼저 확인할 정보성 후보 2건을 함께 표시합니다.
- 중기부 소상공인 통합공고, 서울시 종합지원, 서민금융진흥원 미소금융과 KB·우리은행의 공식 경로는 대표 후보 아래의 추가 확인 목록으로 구분합니다.
- 서울 상권에 적용되지 않는 지방소재 전용 제도는 제외하고, 특정 동네의 상권 점수로 대출 적합성이나 승인 가능성을 계산하지 않습니다.

### 7.2 금융 안전 원칙

- 화면 용어는 “개인 맞춤 대출 추천”이 아니라 **확인할 지원·자금 후보**로 사용합니다.
- 신용점수, 소득, 부채 등 민감한 금융정보는 초기 버전에서 수집하지 않습니다.
- 은행 상품은 공식 대상·확인일·원문 링크를 보여 주는 정보 제공까지만 구현합니다. 금리·한도 비교, 우선순위 점수, 승인 예측, 신청 중개는 관련 등록과 제휴·법률 검토 전에는 진행하지 않습니다.
- 금리·한도·접수 상태에는 기준일과 공식 출처를 표시하고 사용자가 공식 페이지에서 재확인하도록 합니다.

## 8. 개업 후 리뷰 인사이트

### 8.1 사용자 흐름

1. 사용자가 자신의 가게를 검색해 선택하고 소유 또는 관리 권한을 확인합니다.
2. 같은 업종·거리 범위의 비교 가게를 자동으로 구성하고 사용자가 선정 기준과 가게 목록을 확인합니다.
3. 분석·재사용 권한이 확인된 리뷰 제공자에서 메뉴·가격·응대·대기·청결·공간 등 주제를 분류합니다.
4. 내 가게와 주변 가게의 주제별 언급량·긍부정 차이를 비교합니다.
5. 원문 근거가 있는 관찰과 실행 아이디어를 분리해 보여 줍니다.

### 8.2 데이터 원칙

- 네이버 검색 API는 지역 업체 검색결과를 제공하지만 플레이스 리뷰 원문 분석 API로 사용하지 않습니다.
- Google Places API는 리뷰를 제공하지만 장소당 최대 5개이며, 저자 표시와 원문 링크 등 정책을 준수해야 하므로 “전체 리뷰 종합”으로 표현할 수 없습니다.
- 네이버·카카오·Google 지도 화면이나 비공개 엔드포인트에서 리뷰를 크롤링하지 않습니다.
- 초기 프로토타입은 사용자가 권한을 가진 리뷰 내보내기 파일 또는 별도 라이선스가 있는 제공자의 데이터로 검증합니다.
- 리뷰 작성자 개인 식별, 재식별, 감정 단정, 자동 답글 게시를 하지 않습니다.
- 비교 표본 수와 수집 기간을 표시하고 표본이 적으면 결론 대신 데이터 부족을 표시합니다.

## 11. 완료의 정의

- 사용자가 진단 결과를 이해하고 수정할 수 있습니다.
