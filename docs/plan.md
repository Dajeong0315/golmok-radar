# 골목 레이더 구현 PLAN

## 1. 계획 목적

이 문서는 `docs/mvp.md`, `docs/prd.md`, `docs/spec.md`를 실제 구현 순서로 나눕니다. 각 Phase는 구현·실행·테스트를 마친 뒤 다음 Phase로 넘어갑니다. Phase가 끝날 때마다 변경 파일과 테스트 결과를 확인하고 Git 저장점을 남깁니다.

현재는 Phase 0~5 구현을 마쳤으며 비교 화면과 근거 보기, 배포 환경 연결을 순서대로 진행합니다.

## 2. 최종 사용자 흐름

```text
성동구·광진구 상권 지도 탐색
  → 관심 상권을 브라우저에 저장
  → 저장한 상권 중 2~4곳 선택
  → 같은 기준분기로 지표 비교
  → 지표별 원천값·출처·계산식 확인
  → 현장에서 확인할 질문 보기
```

## 3. Phase 진행 규칙

1. 한 번에 한 Phase만 구현합니다.
2. Phase 시작 전에 사용자에게 필요한 키·설정·결정을 먼저 확인합니다.
3. 비밀값은 `.env`에서만 사용하고 코드·문서·Git 출력에 남기지 않습니다.
4. 자동 테스트와 수동 확인 항목이 통과해야 완료로 표시합니다.
5. 실패한 항목을 고치는 동안 다음 Phase 기능을 미리 추가하지 않습니다.
6. Phase 완료 후 해당 작업 파일만 커밋하며, 이번 구현 과정은 사용자 요청에 따라 Phase별로 원격 저장소에 push합니다.

## 4. 구현 Phase

### Phase 0. 프로젝트 기준선과 Git 준비

**목표:** 지금까지 만든 기획·설정 파일을 안전한 첫 저장점으로 만들고 이후 작업 규칙을 고정합니다.

**현재 확인된 상태:**

- [x] `frontend/`, `backend/`, `database/`, `docs/` 폴더 존재
- [x] `.gitignore`, `backend/.env.example` 존재
- [x] README, MVP, PRD, SPEC, PLAN 문서 작성
- [x] `AGENTS.md` 작업 규칙 작성
- [x] 현재 폴더의 Git 저장소와 GitHub 원격 연결 확인
- [x] 비밀값·원천 대용량 파일이 Git 대상에서 제외되는지 확인
- [x] 첫 커밋과 Phase 0 작업 규칙 커밋 확인

**작업:**

1. Git 설치 여부, 저장소 여부, 사용자 이름·이메일 설정 여부를 확인합니다.
2. 루트에 `AGENTS.md`를 작성해 기술 스택, 검증 원칙, 금지 범위, Phase 진행 규칙을 기록합니다.
3. `.gitignore`가 `.env`, 원천 파일, 가상환경, 빌드 결과를 제외하는지 검증합니다.
4. 저장소를 초기화하고 추적 대상 파일 목록을 검토합니다.
5. 기획 문서와 개발 준비 파일을 첫 커밋으로 저장합니다.

**사용자 준비:** Git 작성자 이름·이메일이 설정되지 않은 경우 값이 필요합니다. GitHub 연결과 push는 별도 확인 후 진행합니다.

**완료 조건:** `git status`에 비밀값과 원천 파일이 나타나지 않고 첫 커밋을 확인할 수 있습니다.

### Phase 1. 원천 데이터 수집과 go/no-go 검증

**목표:** 점포·매출·영역·인구 데이터를 동일한 상권 코드와 기준기간으로 사용할 수 있는지 확정합니다.

**작업:**

1. `fetch_population.py --check`로 서울 Open API 서비스명과 컬럼을 확인합니다.
2. 길단위인구 전체 데이터를 API로 받아 원본 CSV와 수집 메타데이터를 저장합니다.
3. 수집 결과의 기준기간, 상권 코드, 총인구·시간대별 인구 컬럼을 확인합니다.
4. 점포·매출·인구·영역 데이터의 성동구·광진구 코드 교집합을 계산합니다.
5. `20254` 공통 사용 가능 여부를 확인하고 `docs/data_sources.md`를 갱신합니다.
6. 인구가 원천 분기 데이터임을 확인하고 `20254` 행을 별도 환산 없이 사용하도록 확정합니다.

**사용자 준비:** `backend/.env`의 `SEOUL_OPEN_API_KEY`가 필요합니다. 키 값은 대화창이나 Git에 공유하지 않습니다.

**검증:**

- API 보고 행 수와 저장 행 수가 일치합니다.
- 필수 컬럼이 모두 존재합니다.
- 성동구·광진구 공식 상권 코드가 영역 데이터와 연결됩니다.
- 인구가 `20254`와 결합되지 않으면 해당 지표를 비교 불가로 유지하고 그 이유를 문서화합니다.

**완료 조건:** 인구 포함 여부와 분기 집계 규칙이 결정되고 데이터 go/no-go 표가 확정됩니다.

### Phase 2. 정규화 스키마와 적재 파이프라인

**목표:** 연도별로 다른 원천 컬럼을 통일하고 서비스가 반복해서 사용할 수 있는 데이터 구조를 만듭니다.

**작업:**

1. 백엔드 Python 프로젝트와 의존성 관리 파일을 구성합니다.
2. 상권, 점포 지표, 매출 지표, 인구 지표, 데이터 출처 테이블을 설계합니다.
3. SQLAlchemy 모델과 Alembic 초기 마이그레이션을 작성합니다.
4. 테스트용 SQLite에서 스키마를 생성할 수 있게 합니다.
5. 2024·2025 점포 컬럼 차이를 정규화합니다.
6. 점포·매출·인구·영역 적재 스크립트와 검증 리포트를 작성합니다.
7. 같은 논리 키의 중복, 필수값 누락, 잘못된 코드가 있으면 적재를 중단합니다.

**선행조건:** Phase 1 완료.

**검증:** 빈 SQLite DB에 마이그레이션과 적재를 반복 실행하고, 상권·분기·업종별 행 수와 중복 여부를 검사합니다.

**완료 조건:** 새 테스트 DB에서 한 명령 흐름으로 스키마 생성과 검증된 데이터 적재를 재현할 수 있습니다.

### Phase 3. 지표 계산과 pytest

**목표:** 비교 화면에서 사용할 모든 수치를 백엔드 코드로 계산하고 손계산 결과와 일치시킵니다.

**작업:**

1. 카페 점포 수, 개업률, 폐업률, 추정매출 조회 로직을 작성합니다.
2. 주중·주말 매출 비중과 건당 평균 결제액 계산 함수를 작성합니다.
3. Phase 1에서 확정된 경우 총·시간대별 유동인구 계산을 작성합니다.
4. 정상 2건, 경계값 2건, 결측·극단값 1건 이상의 엑셀 손계산 기준표를 만듭니다.
5. 손계산 기대값을 pytest에 고정합니다.
6. 분모 0, 원천 행 누락, 검증 전 상태를 0이 아닌 `비교 불가` 상태로 반환합니다.

**선행조건:** Phase 2 완료.

**검증:** 계산 단위 테스트와 데이터 조회 테스트 전체 통과.

**완료 조건:** 손계산 기준표와 pytest 결과가 모두 일치하고 반올림 규칙이 코드·SPEC과 같습니다.

### Phase 4. FastAPI 조회 API

**목표:** 프론트엔드가 상권 탐색·2~4개 비교·근거 조회에 사용할 안정적인 API를 제공합니다.

**작업:**

1. FastAPI 앱, 설정, DB 세션, 오류 응답 구조를 구성합니다.
2. 성동구·광진구 상권 목록·상세 API를 구현합니다.
3. 서로 다른 상권 코드 2~4개를 받는 비교 API를 구현합니다.
4. 지표별 근거 보기 API를 구현합니다.
5. 현장 확인 질문 API를 구현합니다.
6. CORS와 환경별 설정을 최소 범위로 구성합니다.

**선행조건:** Phase 3 완료.

**검증:**

- 2개·3개·4개 비교 성공 테스트
- 1개·5개·중복 코드·없는 코드·미지원 분기 실패 테스트
- 결측값이 `null`과 사유로 반환되는지 확인
- 응답이나 로그에 비밀값이 없는지 확인

**완료 조건:** API 테스트가 통과하고 로컬 Swagger 문서에서 핵심 조회 흐름을 재현할 수 있습니다.

### Phase 5. React 기반 상권 탐색·지도·관심 목록

**목표:** 사용자가 지도에서 상권을 찾고 관심 목록에 저장할 수 있게 합니다.

**작업:**

1. Vite 기반 React + TypeScript 프로젝트를 구성합니다.
2. FastAPI 클라이언트와 공통 타입·오류 처리를 작성합니다.
3. 성동구·광진구 상권 목록과 필터를 구현합니다.
4. 카카오맵에 상권 마커 또는 경계를 표시합니다.
5. 지도·목록에서 관심 상권 추가와 해제를 구현합니다.
6. 관심 상권 코드를 `localStorage`의 `golmok-radar:favorites:v1`에 저장합니다.
7. 관심 목록에서 2~4개를 비교 대상으로 선택하게 합니다.
8. 다섯 번째 선택을 막고 안내 메시지를 표시합니다.

**사용자 준비:** 카카오맵 JavaScript 키와 localhost 도메인 등록이 필요합니다. 키는 프론트 `.env`의 `VITE_` 환경 변수에만 둡니다.

**검증:** 새로고침 후 관심 목록 유지, 추가·삭제, 잘못된 저장 코드 정리, 2~4개 선택, 모바일 화면을 확인합니다.

**완료 조건:** 지도에서 상권을 저장하고 관심 목록에서 비교 대상을 고르는 흐름이 PC와 모바일에서 동작합니다.

---

### Phase 6. 최대 네 상권 비교 화면

**목표:** 관심 목록에서 선택한 2~4개 상권의 지표를 같은 기준분기로 비교합니다.

**작업:**

1. 비교 API와 연결하고 선택 상권·분기·로딩·오류 상태를 관리합니다.
2. 지표별로 2~4개 상권 값을 같은 행 또는 열에 표시합니다.
3. PC에서는 최대 네 상권 비교표를 제공하고 모바일에서는 가로 스크롤 또는 카드 전환을 적용합니다.
4. 금액·비율·점포 수의 단위와 반올림을 일관되게 표시합니다.
5. 결측·미제공·검증 전 값은 `비교 불가`와 사유로 표시합니다.
6. 크고 작음만으로 추천·등급·성공 가능성을 표현하지 않습니다.

**선행조건:** Phase 4와 Phase 5 완료.

**검증:** 데이터가 모두 있는 조합과 일부 없는 조합을 각각 2·3·4개 상권으로 확인합니다.

**완료 조건:** 상권 수와 화면 크기가 달라도 같은 분기·같은 지표가 잘리지 않고 정확히 비교됩니다.

---

### Phase 7. 근거 보기와 현장 체크리스트

**목표:** 모든 숫자를 검증할 수 있게 하고 통계로 알 수 없는 내용을 현장에서 확인하도록 돕습니다.

**작업:**

1. 지표별 근거 보기 패널 또는 화면을 구현합니다.
2. 상권별 제공기관, 데이터셋, 수집일, 기준분기, 코드, 필터, 원천값을 표시합니다.
3. 계산형 지표에는 분자·분모·수식·반올림 규칙을 표시합니다.
4. 원천 행 제공은 재배포 조건 확인 결과에 따라 요약 또는 다운로드로 구현합니다.
5. 현장 확인 질문을 분류해 읽기 전용으로 제공합니다.
6. 화면 값과 손계산 기준표를 표본 상권에서 눈으로 대조합니다.

**선행조건:** Phase 6 완료.

**검증:** 화면에 표시된 모든 숫자에서 근거 보기로 진입할 수 있고 API 원천값·계산 결과와 일치합니다.

**완료 조건:** 근거 없는 수치가 없고, 결측 사유와 추정치의 한계가 사용자에게 보입니다.

---

### Phase 8. Supabase 연결과 통합 마무리

**목표:** 검증된 로컬 구현을 Supabase와 연결하고 전체 MVP를 재현 가능한 상태로 정리합니다.

**작업:**

1. 테스트용 Supabase에 Alembic 마이그레이션을 적용합니다.
2. 검증된 데이터를 Supabase에 적재합니다.
3. FastAPI가 Supabase PostgreSQL을 조회하도록 환경별 연결을 확인합니다.
4. 전체 백엔드·프론트 테스트와 수동 시나리오를 실행합니다.
5. 실행·테스트·데이터 갱신 방법을 README에 작성합니다.
6. 구조도, ERD, API 표, 검증 기록과 한계를 문서화합니다.
7. 공개 저장소에 비밀값과 원천 대용량 파일이 없는지 최종 확인합니다.

**사용자 준비:** 테스트용 Supabase 프로젝트의 연결 정보가 필요하며 `backend/.env.test` 또는 지정한 비밀 환경 변수에만 둡니다.

**검증:** 빈 환경에서 문서 순서대로 설치·마이그레이션·적재·실행·테스트를 재현합니다.

**완료 조건:** PC·모바일 주요 흐름과 SPEC 완료 조건이 모두 통과하고 다른 사람이 README만 보고 실행할 수 있습니다.

## 5. MVP 이후 범위

다음 기능은 Phase 0~8 완료 전에는 구현하지 않습니다.

- 계정 기반 관심 상권 동기화
- 개인 현장 메모 저장
- 비교 리포트 공유
- 전국 상권 확대
- 상권 추천 점수·등급·성공 확률
- 데이터 갱신 자동 스케줄링

## 6. 의존성과 위험 관리

| 항목 | 영향 | 대응 |
| --- | --- | --- |
| 인구 API에 `20254`가 없음 | 인구 지표 비교 불가 | 가능한 최신 공통기간을 검토하거나 인구 지표만 비교 불가 처리 |
| 인구의 월·분기 단위가 다름 | 잘못된 합계 가능 | 원천 정의 확인 전 계산 금지, 집계 규칙을 근거 보기에 명시 |
| 일부 상권에 카페 매출 행이 없음 | 비교표 일부 결측 | 0으로 바꾸지 않고 비교 불가와 사유 표시 |
| 카카오맵 키·도메인 설정 오류 | 지도 미표시 | Phase 5 시작 전 localhost 등록과 키 로딩 확인 |
| 브라우저 저장소 삭제·기기 변경 | 관심 목록 소실 | MVP 한계를 화면에 안내하고 계정 동기화는 후속 범위로 분리 |
| 원천 파일 재배포 제한 | 원천 행 다운로드 제한 | 라이선스 확인 전에는 원천값 요약과 행 식별 정보만 제공 |
