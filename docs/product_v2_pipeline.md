# 골목 레이더 V2 — 오프라인 창업 첫 파이프라인

> 범위 구분: 소개형 홈과 계정 기록함은 plan.md Phase 23~28에서 완료했습니다. 화면 요구는 prd.md 11절, 비로그인 60분 미활동 만료·로그인 시 유효 기록 이관·재시험 보존 계약은 spec.md 12절을 따릅니다. 아래 localStorage 전용/서버 저장 제외는 최초 구현 범위이며 계정 저장 기능이 이를 대체했습니다. 전체 업종 확장은 plan.md Phase 29~33의 후속 계획입니다. 실매물 자동 수집·공개 공유·성공 예측은 계속 제외합니다.

## 1. 제품 컨셉

골목 레이더 V2는 “상권 숫자 비교 도구”를 넘어, 상권 통계와 사용자의 현장·매물 검증을 한 흐름으로 남겨 첫 계약 전의 확인 누락을 줄이는 도구입니다. 창업 성공, 계약 안전성, 수익, 대출 승인 가능성을 예측하거나 상권·매물을 추천하지 않습니다.

```text
1. 탐색: 창업 성향·예산·운영 조건 정리 → 서울 공식 상권 후보 탐색 → 같은 기준분기·업종 지표 비교
2. 검증: 사용자 직접 매물 후보 입력 → 현장 관찰 기록 → 공간비·시설·인허가 확인 항목 점검
3. 의사결정 준비: 공식 지원·자금 정보 확인 → 계약 전 공식 문서 또는 전문가 확인 필요 항목 표시 → 계약 여부는 판정하지 않음
4. 운영 개선: 개업 후 권한 있는 리뷰 데이터로 고객 반응·주변 경쟁점 비교
```

Phase 16에서 서울 공식 상권 1,650곳으로 넓힌 탐색·2~4곳 비교·근거 보기는 이 파이프라인의 **상권 판단 엔진**으로 유지합니다. Phase 19 워크시트는 V2 별도 기능이며 기존 상권 비교 API와 계산 계약을 변경하지 않습니다.

## 3. 창업 성향 진단

### 3.1 표시 원칙

- 기능명은 “심리 진단”이 아니라 **창업 성향 진단**으로 표시합니다.
- 임상·심리 검사나 성공 가능성 예측이 아니며, 답변은 후보 탐색 기준을 정리하는 데만 사용합니다.
- 로그인 전 답변과 결과는 브라우저에 저장합니다. 서버 저장은 명시적 동의와 계정 기능이 생긴 뒤에만 합니다.
- 결과 화면에서 사용자는 업종·예산·선호를 직접 수정할 수 있어야 합니다.

### 3.2 6개 질문과 선택지

| 번호 | 질문 | 선택지 4개 | 반영 축 |
| --- | --- | --- | --- |
| Q1 | 지금 가장 먼저 열어 보고 싶은 가게는 무엇인가요? | 카페·디저트 / 식당·주점 / 소매·편집숍 / 생활서비스·스튜디오 | 업종 |
| Q2 | 어떤 손님이 자주 찾아오는 가게를 만들고 싶나요? | 동네 단골 / 직장인 / 목적 방문객 / 저녁 손님 | 수요 유형 |
| Q3 | 첫 가게의 비용은 어떤 방식으로 정하고 싶나요? | 작게 시작 / 비용·성장 균형 / 기회에 투자 / 숫자부터 확인 | 위험·예산 |
| Q4 | 문을 연 뒤에는 누가 가게를 운영할 계획인가요? | 1인 / 가족·동업자 / 직원과 팀 / 커뮤니티 중심 | 운영 역량 |

| Q6 | 근처에 비슷한 가게가 많다면 어떻게 느낄 것 같나요? | 경쟁 적은 곳 / 확인된 수요 / 차별화 경쟁 / 유동 우선 | 경쟁 선호 |

### 3.3 결과 유형

답변을 단일 성격 유형으로 단정하지 않고 네 축을 보여 줍니다.

- 업종 관심: 카페·외식·소매·서비스
- 수요 선호: 생활권·업무권·목적방문·야간
- 운영 성향: 소형 효율·균형 운영·확장 운영·관계 중심
- 위험 선호: 보수·균형·성장

결과 예시: `생활권 단골을 만드는 소형 효율형 · 카페/디저트 관심`. 각 축별로 어떤 답변이 반영됐는지 공개합니다.

## 4. 조건 기반 탐색 후보 상권 2~3곳

### 4.1 자동 추천이 아닌 조건 기반 후보 정리

화면 문구는 “성공할 상권”이 아닌 **조건이 잘 맞는 탐색 후보**로 표현합니다. 사용자의 업종·운영 조건을 충족하는 상권만 남긴 뒤 아래 데이터로 적합도를 계산합니다.

1. 업종 데이터가 존재하는 상권만 필터링합니다.
2. 사용자의 필수 조건(지역, 업종, 예산 상한)을 먼저 적용합니다.
3. 유동인구 시간대, 주중·주말 매출, 점포 수, 개·폐업률을 각 상권 집단 내 백분위로 변환합니다.
4. 답변 축과 지표의 명시된 가중치를 적용합니다.
5. 같은 이유의 후보만 몰리지 않도록 최대 3곳을 다양화합니다.
6. 점수, 기여 지표, 제외 조건, 데이터 기준분기를 사용자에게 공개합니다.

초기 V2는 현재 검증된 카페 업종에서만 조건 기반 탐색 후보를 정리합니다. 다른 업종을 선택하면 성향 결과는 보여주되, 해당 업종 데이터 검증이 끝날 때까지 “준비 중”과 수동 상권 탐색을 제공합니다.

### 4.2 탐색 후보 카드

- 상권명·자치구·상권 유형
- 조건과 연결된 근거 2~3개
- 주의 신호 1~2개
- 기준분기와 데이터 완전성
- 관심 상권 저장, 기존 비교 화면에 추가
- 후보 정리 기준 상세 보기

## 5. 상권별 확인 신호·주의 신호 리포트

리포트는 생성형 AI가 수치를 새로 만들지 않고 검증된 지표의 상대 위치를 문장으로 바꿉니다.

- 확인 신호: 비교 모집단의 상위 30%인 검증 지표
- 주의 신호: 하위 30%이거나 원천 데이터가 누락된 지표
- 중립: 나머지 지표
- 모든 문장은 수치·비교 모집단·기준분기·근거 보기로 연결
- “성공 가능”, “핫플 보장”, “무조건 유리” 같은 표현 금지

예: “주말 매출 비중이 비교 가능한 서울 카페 상권 중 상위 30%입니다. 반면 개업률과 폐업률이 모두 높아 경쟁 변동성을 현장에서 확인해야 합니다.”

## 6. 임대 데이터와 매물

### 6.1 단계별 제공

1. **공식 임대 벤치마크**: 한국부동산원의 상업용부동산 임대동향조사에서 상권별 임대료·공실률·임대가격지수를 분기 단위로 제공합니다.
2. **사용자 입력 예산 시뮬레이터**: 보증금, 월세, 관리비, 면적을 사용자가 입력하면 월 고정비와 매출 대비 부담을 계산합니다.
3. **개별 매물 정보**: 사용자가 직접 입력한 워크시트만 제공합니다. 제휴 여부와 관계없이 이번 제품 범위에서는 매물 목록 연결·자동 수집을 제안하거나 구현하지 않습니다.

2026-11-02부터 R-ONE 원본에 포함된 서울 세부 조사상권 59곳의 임대료·공실률·임대가격지수를 서울 전체 평균과 함께 제공합니다. 서울시 골목상권과 R-ONE 조사상권은 경계가 다르므로 서비스가 자동으로 같은 상권이라고 단정하지 않고 사용자가 가까운 공식 조사상권을 직접 선택합니다. 입력 면적을 이용한 환산 참고액과 실제 매물의 보증금·월세 입력값도 서로 분리합니다.

### 6.2 네이버 부동산 처리 원칙

2026-10-29 확인 기준 NAVER Developers 공개 API 목록에는 부동산 매물 API가 확인되지 않았습니다. 비공개 엔드포인트 호출, 화면 크롤링, 로그인 우회는 구현하지 않습니다. 제휴 API와 재사용 권한이 확인되기 전에는 네이버 부동산으로 이동하는 검색 링크만 제공할 수 있습니다.

공식 임대 통계는 실제 개별 매물 가격이 아니라 분기 표본 통계이므로 화면에서 “실시간 매물”로 표현하지 않습니다.

### 6.3 사용자 입력 매물 검증 워크시트 (Phase 19)

워크시트는 매물 자동 수집이 아니라 사용자가 직접 입력·확인하는 기능입니다. 서울시 골목상권 통계, R-ONE 임대 벤치마크, 사용자 입력 매물 데이터는 각각 출처·기준기간 또는 입력일·공간 단위를 구분해 표시하며 서로 대체하지 않습니다.

**입력 항목:** 매물 별칭, 주소 또는 사용자가 식별 가능한 위치 설명, 층수, 전용면적과 단위, 보증금, 월세, 관리비, 부가세 포함 여부 또는 확인 상태, 권리금, 중개수수료, 인테리어·설비 등 초기 비용 추정치, 선택 입력인 예상 월매출.

**자동 계산:** 초기 투입비 = 보증금 + 권리금 + 중개수수료 + 초기 비용, 월 공간비 = 월세 + 관리비, 면적당 월 공간비 = 월 공간비 ÷ 전용면적, 월 공간비 대비 예상 월매출 비율 = 월 공간비 ÷ 예상 월매출 × 100. 마지막 비율은 사용자가 0보다 큰 예상 월매출을 입력한 경우에만 계산하며 서비스가 예상 월매출을 추정하지 않습니다.

금액은 원 단위의 0 이상 정수, 전용면적은 0보다 큰 수와 `㎡` 또는 `평` 단위를 함께 기록합니다. `평`은 `1평 = 3.305785㎡`로 환산해 `원/㎡`를 계산하되 원입력 단위를 함께 표시합니다. 필요한 입력값이 없거나 분모가 0·누락이면 0으로 보정하지 않고 `입력 필요` 또는 `비교 불가`와 사유를 표시합니다. 입력값·단위·계산식·계산 불가 사유는 모두 확인할 수 있어야 합니다.

현장 확인은 평일/주말과 오전/점심/저녁 관찰 시점, 보행 흐름과 실제 카페 이용 가능성, 인접 경쟁점·좌석·대기·공실, 전면 폭·가시성·출입 동선, 전기·급배수·배기·화장실·주차·상하차, 소음·악취·공사 제약을 기록합니다. 건축물 용도, 영업 가능 여부, 임대차 특약, 원상복구는 계약 전 확인 항목으로 기록합니다. 각 항목의 상태는 `확인 완료`, `추가 확인`, `해당 없음`, `기록 없음` 중 하나로만 표시하며, 법률·인허가·계약 항목에는 **공식 기관 또는 전문가 확인 필요**를 표시합니다. 서비스는 이를 판정하거나 계약 여부를 결정하지 않습니다.

로그인 없는 MVP에서는 워크시트를 브라우저 localStorage에만 저장합니다. 서버 저장, 주소 기반 자동 조회, 제휴 매물 API, 실매물 자동 수집, 비공개 API 호출, 화면 크롤링, 로그인 우회는 구현하거나 제안하지 않습니다.

## 7. 창업 지원·자금 후보 2건

### 7.1 1차 범위

- K-Startup 공식 지원사업 공고 API에서 모집 중인 사업을 수집합니다.
- 업종, 지역, 예비/기창업, 업력, 대표자 연령 등 공개된 자격 조건으로 필터링합니다.
- 조건이 많이 맞는 후보 2건을 보여 주고, 일치·불일치·확인 필요 조건을 각각 표시합니다.
- 신청은 공식 상세 페이지로 이동하며 서비스가 승인 가능성이나 금리를 보장하지 않습니다.
- 진단 결과에는 IBK기업은행·KDB산업은행 공식 안내 중 사업 단계와 자금 용도에 따라 먼저 확인할 정보성 후보 2건을 함께 표시합니다.
- 중기부 소상공인 통합공고, 서울시 종합지원, 서민금융진흥원 미소금융과 KB·우리은행의 공식 경로는 대표 후보 아래의 추가 확인 목록으로 구분합니다.
- 서울 상권에 적용되지 않는 지방소재 전용 제도는 제외하고, 특정 동네의 상권 점수로 대출 적합성이나 승인 가능성을 계산하지 않습니다.

### 7.2 금융 안전 원칙

- 화면 용어는 “개인 맞춤 대출 추천”이 아니라 **확인할 지원·자금 후보**로 사용합니다.
- 신용점수, 소득, 부채 등 민감한 금융정보는 초기 버전에서 수집하지 않습니다.
- 은행 상품은 공식 대상·확인일·원문 링크를 보여 주는 정보 제공까지만 구현합니다. 금리·한도 비교, 우선순위 점수, 승인 예측, 신청 중개는 관련 등록과 제휴·법률 검토 전에는 진행하지 않습니다.
- 금리·한도·접수 상태에는 기준일과 공식 출처를 표시하고 사용자가 공식 페이지에서 재확인하도록 합니다.

## 8. 개업 후 리뷰 인사이트

### 8.1 사용자 흐름

1. 사용자가 자신의 가게를 검색해 선택하고 소유 또는 관리 권한을 확인합니다.
2. 같은 업종·거리 범위의 비교 가게를 자동으로 구성하고 사용자가 선정 기준과 익명 비교군 수를 확인합니다.
3. 분석·재사용 권한이 확인된 리뷰 제공자에서 메뉴·가격·응대·대기·청결·공간 등 주제를 분류합니다.
4. 내 가게와 주변 가게의 주제별 언급량·긍부정 차이를 비교합니다.
5. 원문 근거가 있는 관찰과 실행 아이디어를 분리해 보여 줍니다.

### 8.2 데이터 원칙

- 네이버 검색 API는 지역 업체 검색결과를 제공하지만 플레이스 리뷰 원문 분석 API로 사용하지 않습니다.
- Google Places API는 리뷰를 제공하지만 장소당 최대 5개이며, 저자 표시와 원문 링크 등 정책을 준수해야 하므로 “전체 리뷰 종합”으로 표현할 수 없습니다.
- Google 지도 화면과 모든 비공개 엔드포인트에서 리뷰를 수집하지 않습니다.
- Phase 17 자동 흐름은 카카오 공개 화면의 제한 표본(같은 가게·같은 달 재사용, 사용자별 신규 수집 월 5회, 실행당 최대 5개 가게·가게당 20개 리뷰)과 사용자 제공 리뷰 입력으로 검증합니다. 네이버 공개 화면 파일럿은 429 응답으로 종료했고 자동 연결은 후속 adapter로 둡니다. 로그인·CAPTCHA·차단 우회와 병렬·상시 대량 수집은 금지합니다.
- 리뷰 작성자 개인 식별, 재식별, 감정 단정, 자동 답글 게시를 하지 않습니다.
- 비교 표본 수와 수집 기간을 표시하고 표본이 적으면 결론 대신 데이터 부족을 표시합니다.

## 11. 완료의 정의

- 사용자가 진단 결과를 이해하고 수정할 수 있습니다.
- 조건 기반 탐색 후보마다 조건 연결 근거와 주의 신호의 수치 근거를 확인할 수 있습니다.
- 서울시 상권 통계, R-ONE 임대 벤치마크, 사용자 입력 매물 정보를 서로 혼동하지 않습니다.
- 워크시트는 계산 근거와 현장·계약 전 확인 상태를 남기되 계약 여부를 판정하지 않습니다.
- 자금 후보는 자격 조건과 기준일을 보여 주고 공식 신청처로 연결합니다.
- 리뷰 분석은 데이터 권한·표본 수·출처를 명확히 표시합니다.
- 각 기능은 외부 키가 없어도 fixture와 계약 테스트로 재현 가능해야 하며, 실제 연동 완료와 구현 완료를 구분합니다.

## 11. 소개형 홈과 계정 기록함 확장 (Phase 23~28)

- 서비스 소개와 사용 흐름을 홈에 통합하고 지도 탐색을 분리합니다. 마이페이지는 테스트 결과·저장 상권·후보/비교 리포트·매물 워크시트·계정 관리를 제공합니다.
- 비로그인 이용 기록은 마지막 실제 활동 후 60분 동안 보관합니다. 최초 안내, 작은 상시 안내, 20분 간격 로그인 권유, 만료 10분/2분 전 예고를 제공합니다. 재방문만으로 즉시 지우지 않습니다.
- 로그인 시 유효한 테스트 결과 이력·상권분석 리포트·관심 상권·매물·초안 전체를 기존 계정 기록과 자동 병합합니다. 서버 저장 확인 전 임시본 삭제 금지, 로그인 왕복/부분 실패/재시도 중 보존은 spec.md 12절을 따릅니다.
- 기존 테스트 결과 보기 옆에 테스트 다시 해보기를 제공합니다. 새 초안·새 결과를 만들고 이전 결과는 보존합니다. 이름 변경·삭제는 마이페이지에서 제공합니다.
- 구현 순서·준비 사항·검증 기준·완료 결과는 plan.md Phase 23~28에 기록했습니다. 전체 업종과 가게 위치 확인은 Phase 29~33에서 진행합니다.
