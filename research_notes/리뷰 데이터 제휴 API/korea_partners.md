# 국내 정식 리뷰 데이터 제휴 후보 조사

조사 기준일: 2026-10-31  
대상: 서울 카페의 `내 가게 + 주변 동종 경쟁점` 리뷰를 자동 수집해 분석하고, 서비스 화면에 분석 결과 또는 허용된 리뷰 내용을 표시할 수 있는 정식 데이터/API 계약

## 어떤 공급자부터 접촉해야 하는가?

### Takeaway

1차 제휴 문의 순서는 **식신 → 다이닝코드 → 레드테이블**이 타당하다. 식신과 다이닝코드는 자체 음식점·리뷰 서비스를 운영할 뿐 아니라, 이용약관에 회사 또는 허락된 제3자가 회원 리뷰를 제휴 서비스에 표시·편집·복제·전송·배포할 수 있는 근거가 공개돼 있다. 식신은 별도의 맞춤형 AI 데이터 서비스와 API 연동도 공식적으로 안내한다. 레드테이블은 공식 문화 빅데이터 플랫폼에서 레스토랑 DaaS 사업자로 소개되지만, 공개 상품에서 리뷰 원문 제공권은 확인되지 않았다. [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html), [식신 AI 데이터 서비스](https://alipay.siksinhot.com/aidata), [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php), [문화 빅데이터 플랫폼의 레드테이블 소개](https://www.bigdata-culture.kr/bigdata/user/data_market/agency/detail.do?id=redtable_org)

### Cited Findings

- 식신은 MetaDex를 통해 공공·민간 데이터 수집·정제, 웹 크롤링·API 연동, 리뷰·블로그 기반 정성 데이터 마이닝과 고객 맞춤 데이터 제공을 공식 안내하고 별도 문의 양식을 운영한다. [식신 AI 데이터 서비스](https://alipay.siksinhot.com/aidata)
- 식신 약관은 식신 리뷰를 회원이 매장에 남긴 점수·글·사진·동영상으로 정의하고, 회사 또는 회사가 허락한 제3자가 회사 사업과 관련된 제휴 웹사이트·플랫폼·앱에 게시물을 표시하고 필요한 범위에서 수정·편집·복제·전송·전시·배포할 수 있으며 유상 또는 무상으로 사용할 수 있다고 명시한다. [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html)
- 다이닝코드는 페이지 하단에 `데이터 제휴 문의`와 `contact@diningcode.com`을 공개한다. [다이닝코드 데이터 제휴 문의](https://www.diningcode.com/profile.php?rid=eDOEEXwuxAez)
- 다이닝코드 약관은 Open API 서비스를 제반 서비스에 포함하고, 회원 리뷰를 회사 사업 관련 제3자에게 유·무상으로 일부 수정·편집해 복제·전송·전시·배포할 수 있다고 명시한다. [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php)
- 문화 빅데이터 플랫폼은 레드테이블을 레스토랑 빅데이터 DaaS 제공 기업으로 소개하고 `bigdata@redtable.kr`, `02-6964-7955`를 공개한다. [레드테이블 기관 소개](https://www.bigdata-culture.kr/bigdata/user/data_market/agency/detail.do?id=redtable_org)

### Inferences

- **식신과 다이닝코드는 “리뷰를 보유한다”는 사실만 확인된 후보보다 계약 가능성이 높다.** 두 회사의 공개 약관에 제휴 제3자에 대한 게시물 이용 근거가 있기 때문이다. 다만 이 약관은 골목 레이더에 자동으로 권리를 부여하지 않으며, 경쟁점 리뷰의 분석·저장·표시가 포함된 별도 B2B 계약이 반드시 필요하다.
- **레드테이블은 데이터 회사로서의 신뢰성은 높지만 리뷰 원문 공급자로는 아직 미검증이다.** 첫 문의에서 원천 리뷰의 출처와 재라이선스 권리를 증명하지 못하면 후보에서 제외하는 편이 안전하다.

### Gaps

- 모든 상위 후보에서 공개되지 않은 항목: 서울 카페 매장 수, 매장당 리뷰 수와 최근 리뷰 비율, 가격, 호출량, SLA, 원문 제공 여부, 출처표시, 캐시·영구저장, 파생 감성·주제 분석, LLM 입력, 화면 표시, 삭제·정정 동기화, 계약 종료 후 데이터 처리.
- 공개 페이지의 “데이터 제공” 또는 “API” 문구만으로 경쟁점 리뷰 원문을 재사용할 권리가 생기지는 않는다.

## 네이버 스마트플레이스와 카카오맵의 공개 API로 경쟁점 리뷰를 받을 수 있는가?

### Takeaway

**현재 공개된 네이버 지역 검색 API와 카카오 로컬 API는 장소 탐색용 메타데이터에는 쓸 수 있지만 리뷰 원문 수집에는 쓸 수 없다.** 네이버는 장소명·링크·분류·설명·주소·좌표를, 카카오는 장소 ID·이름·분류·전화·주소·좌표·상세 URL·거리를 반환한다고 문서화하며 리뷰 텍스트 필드를 공개하지 않는다. [네이버 지역 검색 API 응답](https://developers.naver.com/docs/serviceapi/search/local/local.md), [카카오 로컬 API 응답](https://developers.kakao.com/docs/ko/local/dev-guide)

### Cited Findings

- 네이버 지역 검색 API는 네이버 지역 서비스에 등록된 업체·기관을 반환하며 일 호출 한도는 25,000회이고, 한 요청의 표시 결과는 최대 5개다. `comment` 정렬은 카페·블로그 리뷰 **개수순** 정렬일 뿐 리뷰 원문 필드는 아니다. [네이버 지역 검색 API](https://developers.naver.com/docs/serviceapi/search/local/local.md)
- 네이버 지역 검색 API의 공개 응답 필드는 업체명, 상세 URL, 분류, 설명, 주소, 도로명 주소, 좌표 등이며 리뷰 본문은 포함되지 않는다. [네이버 응답 필드](https://developers.naver.com/docs/serviceapi/search/local/local.md)
- 네이버는 스마트플레이스 사업주용 리뷰 관리 솔루션에서 새 리뷰의 표현 수위와 맥락을 AI로 분석해 민감 이슈를 알리고 답글 초안을 제안한다고 설명한다. 이는 네이버 내부의 사업주 지원 기능으로 소개된 것이며 외부 경쟁점 리뷰 API로 설명되지 않았다. [네이버 스마트플레이스 리뷰 관리 솔루션](https://www.navercorp.com/media/pressReleasesDetail?seq=34203)
- 네이버는 브랜드 가맹점이 자체 회원 관리 시스템을 플레이스 멤버십과 연동할 때 `네이버 플레이스 제휴 제안 채널`로 별도 요청할 수 있다고 밝혔다. 해당 공개 사례의 제휴 대상은 CRM·멤버십 연동이지 리뷰 원문 라이선스가 아니다. [네이버 플레이스 CRM 연동 보도자료](https://www.navercorp.com/media/pressReleasesDetail?seq=10034259)
- 카카오 로컬 API는 좌표·반경·카테고리로 주변 장소를 검색하고 장소 ID, 이름, 분류, 전화번호, 주소, 좌표, 카카오맵 상세 URL, 거리를 반환한다. 공개 응답 명세에 리뷰 텍스트 필드는 없다. [카카오 로컬 API](https://developers.kakao.com/docs/ko/local/dev-guide)

### Inferences

- 네이버·카카오는 골목 레이더에서 **주변 카페 후보 탐색과 장소 식별** 용도로는 유용하지만, 리뷰 분석 데이터 공급자로 간주하면 안 된다.
- 네이버에 제휴 제안을 보낼 경우 “사업주 본인 매장 리뷰 관리”가 아니라 “서울 카페 경쟁점까지 포함한 원문 또는 익명화된 리뷰 신호의 B2B 이용”이라고 범위를 명확히 써야 한다. 공개된 제휴 사례가 다른 목적이므로 승인 가능성은 낮게 잡는 편이 보수적이다.
- 카카오의 공개 문서에서 리뷰 데이터 제휴 채널을 찾지 못했으므로, 카카오 리뷰를 전제로 개발하거나 비공개 엔드포인트를 역분석해서는 안 된다.

### Gaps

- 네이버·카카오 모두 공개 문서에서 경쟁점 리뷰 원문에 대한 B2B 가격, API, 저장 기간, 파생분석, 화면 표시 또는 재라이선스 조건을 확인하지 못했다.
- “공개 페이지에서 볼 수 있다”는 사실은 자동수집·저장·상업적 분석 권리를 의미하지 않는다.

## 식신은 실제 리뷰 원문 제휴에 적합한가?

### Takeaway

식신은 이번 조사에서 **가장 먼저 기술·법무 샘플을 요청할 후보**다. 공식 데이터 서비스가 리뷰·블로그 기반 정성 데이터 마이닝, 맞춤 데이터, API 연동과 데이터 제공을 명시하고, 이용약관은 식신 자체 리뷰에 대한 제휴 제3자의 표시·편집·복제·전송·배포 가능성을 명시한다. [식신 AI 데이터 서비스](https://alipay.siksinhot.com/aidata), [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html)

### Cited Findings

- 식신은 위치 기반 음식점 추천·검색 서비스이며 `식신리뷰`를 회원이 매장에 직접 남긴 평가점수, 글, 사진, 동영상으로 정의한다. [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html)
- 식신 회원은 회사 또는 회사가 허락한 제3자가 게시물을 회사 사업과 관련된 제휴 웹사이트·플랫폼·앱에 공개적으로 표시하고, 필요한 범위에서 수정·편집해 복제·전송·전시·배포하는 것을 허락한다. 회사는 이 목적을 위해 게시물을 유상 또는 무상으로 사용할 수 있다고 약관에 명시한다. [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html)
- 회원은 게시물 삭제·비공개 조치를 요청할 수 있고, 회원이 탈퇴할 때 리뷰·별점·사진 등 본인 계정의 게시물은 삭제된다고 약관에 적혀 있다. [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html)
- 식신의 AI 데이터 서비스는 맞춤 데이터 모델, 리뷰·블로그 기반 정성 데이터 마이닝·키워드 분류, API 연동 데이터 확보, 데이터 제공·유지보수를 안내하고 서비스 문의 양식을 제공한다. [식신 AI 데이터 서비스](https://alipay.siksinhot.com/aidata)

### Inferences

- 약관상 제휴 활용 근거와 별도 데이터 사업이 함께 존재하므로, 식신 자체 리뷰를 정식으로 공급받는 계약을 논의할 실질적 근거가 있다.
- 다만 AI 데이터 서비스가 `웹 크롤링`도 제공한다고 적은 만큼, 제안받는 샘플에 식신 자체 리뷰와 제3자 플랫폼에서 수집한 콘텐츠가 섞여 있을 수 있다. 계약 전 **각 레코드의 원천과 재라이선스 권리**를 분리해 증명받아야 한다.
- 게시물 삭제권이 있으므로 리뷰 ID별 삭제·정정 피드 또는 짧은 캐시 TTL이 계약·기술 요건에 포함돼야 한다.

### Gaps

- 공개 문서에는 서울 카페 커버리지, 장소 식별자, 매장별 리뷰 밀도, 리뷰 작성일·평점·원문 필드, 증분 갱신, 가격, SLA가 없다.
- 골목 레이더가 리뷰 원문을 저장하거나 요약·감성·주제 분석 결과를 사용자에게 보여줄 권리, LLM 처리 가능 여부, 리뷰 일부 인용 길이와 출처표시 방식은 계약서에서 확인해야 한다.

## 다이닝코드는 실제 리뷰 원문 제휴에 적합한가?

### Takeaway

다이닝코드는 **식신과 함께 1차 제휴 문의를 보낼 후보**다. 공식 사이트가 데이터 제휴 문의 이메일을 공개하고, 이용약관에 Open API 서비스와 회원 리뷰의 유·무상 제3자 제공·편집·복제·전송·전시·배포 근거가 있다. [다이닝코드 데이터 제휴 문의](https://www.diningcode.com/profile.php?rid=eDOEEXwuxAez), [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php)

### Cited Findings

- 다이닝코드 페이지는 `데이터 제휴 문의`와 `contact@diningcode.com`을 공개한다. [다이닝코드 제휴 문의](https://www.diningcode.com/profile.php?rid=eDOEEXwuxAez)
- 다이닝코드 이용약관은 제반 서비스에 개발자·서비스 제공자를 위한 다이닝코드 Open API와 이를 이용한 응용 애플리케이션·웹서비스가 포함된다고 정의한다. [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php)
- 회원이 작성한 게시물의 권리는 회원에게 있지만, 회원은 리뷰·사진·동영상·링크·체크인 등을 회사 사업 관련 제3자에게 유상 또는 무상으로 필요한 범위에서 수정·편집해 복제·전송·전시·배포하는 것을 허락한다고 약관에 명시돼 있다. [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php)
- 회원은 탈퇴 후에도 본인이 작성한 게시물 삭제를 요구할 수 있고 회사는 이를 삭제해야 한다고 약관에 적혀 있다. [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php)

### Inferences

- 공개 API 문서가 보이지 않더라도 이용약관의 Open API 정의와 명시적 데이터 제휴 연락처는 폐쇄형 B2B API·파일 공급 가능성을 문의할 충분한 근거다.
- 리뷰 권리는 작성자에게 남아 있고 삭제 요구가 가능하므로, 계약에는 리뷰 ID, 삭제·정정 피드, 삭제 반영 SLA, 계약 종료 시 파기 절차가 필요하다.
- 다이닝코드 페이지에는 회원 리뷰와 외부 블로그 후기 등이 함께 보일 수 있으므로, 제휴 샘플은 **다이닝코드 회원이 직접 작성한 리뷰만** 별도 원천 코드로 제공하도록 요구해야 한다.

### Gaps

- 공개 개발자 문서, API 엔드포인트, 가격, 호출 한도, 데이터 신선도, 서울 카페 커버리지, 원문 표시·저장·파생분석 조건을 확인하지 못했다.
- 약관의 제휴 활용 허용만으로 골목 레이더의 구체적 이용 목적이 자동 승인되는 것은 아니다.

## 레드테이블은 리뷰 데이터 공급자로 적합한가?

### Takeaway

레드테이블은 **데이터 전문 공급자라는 점은 확인되지만 리뷰 원문 후보로는 조건부**다. 공식 문화 빅데이터 플랫폼은 레드테이블을 레스토랑 DaaS 제공 기업으로 소개하지만, 공개된 데이터 사례는 식당·메뉴·품질·테마 정보 중심이며 서울 카페의 사용자 리뷰 원문 공급권은 확인되지 않았다. [레드테이블 기관 소개](https://www.bigdata-culture.kr/bigdata/user/data_market/agency/detail.do?id=redtable_org), [K-Food 연계 데이터](https://www.bigdata-culture.kr/bigdata/user/content.do?sq=77)

### Cited Findings

- 문화 빅데이터 플랫폼은 레드테이블을 레스토랑 빅데이터 DaaS, 홍보마케팅, 상품 판매 서비스를 제공하는 기업으로 소개하고 공식 문의 이메일과 전화번호를 제공한다. [레드테이블 기관 소개](https://www.bigdata-culture.kr/bigdata/user/data_market/agency/detail.do?id=redtable_org)
- 문화 빅데이터 플랫폼의 K-Food 서비스가 열거한 레드테이블 연계 데이터는 식당, 식당 서비스 정보, 메뉴, 메뉴 속성, 전통 식당, 무슬림 친화 식당, 할랄 메뉴, 장애인 인증 식당, 외국인 인기 맛집, 지자체 인증 식당 등이다. 해당 페이지는 리뷰 원문 데이터셋을 열거하지 않는다. [K-Food 활용 데이터](https://www.bigdata-culture.kr/bigdata/user/content.do?sq=77)
- 문화 빅데이터 플랫폼의 한 유료 융복합 상품은 레드테이블의 무슬림 친화 식당 정보와 야놀자 숙박정보를 제공하며 가격 11,000,000원, CSV, 비정기 갱신으로 공개돼 있다. 이는 리뷰 원문 상품이 아니라 공개 가격 구조가 존재하는 데이터 상품의 사례다. [무슬림 친화 식당 인근 숙박정보 상품](https://www.bigdata-culture.kr/bigdata/user/data_market/detail.do?id=c2d8efb0-41c2-11eb-af9a-4b03f0a582d6)

### Inferences

- 레드테이블은 맞춤 데이터 계약·납품 역량을 보유했을 가능성이 높지만, 현재 공개 근거만으로는 사용자 리뷰 원문 라이선스 공급자라고 평가할 수 없다.
- 첫 통화에서 `자체 수집 리뷰`, `제휴 플랫폼 리뷰`, `블로그·SNS 가공 신호`를 구분하고 각 원천의 재라이선스 권리를 서면으로 요구해야 한다.

### Gaps

- 서울 카페 사용자 리뷰 원문 보유 여부, 원천 플랫폼, 작성자 약관, API 제공, 실시간성, 가격, 저장·표시·파생분석 권리가 모두 미확인이다.
- 공개된 11,000,000원 사례는 다른 데이터셋의 가격이므로 리뷰 데이터 견적으로 전용할 수 없다.

## 공공 관광 데이터나 소셜 리스닝 API가 대안이 될 수 있는가?

### Takeaway

**공공 관광 API는 장소·관광 콘텐츠 보강용이고, 썸트렌드는 소셜 반응 집계용이다. 둘 다 서울 카페별 경쟁점 리뷰 원문 API를 대체하지 못한다.** 한국관광공사 TourAPI는 저작권 등에 구애 없이 활용 가능한 관광정보만 선별해 장소·소개·이미지 등 15종을 제공하고, 썸트렌드 Social Data+는 블로그·커뮤니티·인스타그램 등의 언급량·연관어·감성어를 제공한다. [한국관광공사 국문 관광정보 API](https://www.data.go.kr/data/15101578/openapi.do?recommendDataYn=Y), [썸트렌드 Social Data+](https://data.some.co.kr/social/intro)

### Cited Findings

- 한국관광공사 국문 관광정보 서비스는 지역·위치·키워드·숙박·공통·소개·이미지 등 15종 약 26만 건을 REST JSON/XML로 제공하며, 비용은 무료이고 이용허락범위 제한 없음으로 표시된다. 공개 설명에는 사용자 리뷰 원문 항목이 없다. [공공데이터포털 TourAPI](https://www.data.go.kr/data/15101578/openapi.do?recommendDataYn=Y)
- 한국관광콘텐츠랩은 OpenAPI 콘텐츠에 대해 캐싱·크롤링을 통한 무단 사용을 금지하고, 운영계정은 개발 이력과 서비스 URL 등을 심사한다고 안내한다. [한국관광콘텐츠랩](https://conlab.visitkorea.or.kr/)
- 썸트렌드 Social Data+는 블로그, 커뮤니티·카페, 인스타그램, 유튜브, 뉴스 등에서 키워드 언급량, 연관어, 감성어를 HTTPS REST API와 JSON으로 제공한다고 설명한다. [Social Data+ 소개](https://data.some.co.kr/social/intro), [Social API 문서](https://data.some.co.kr/social/api)
- 썸트렌드 API의 공개 응답 예시는 문서 수, 날짜별 빈도, 연관어와 감성어 등 집계·분석값 중심이다. [Social API 문서](https://data.some.co.kr/social/api)
- 썸트렌드 MCP 개인정보 처리방침은 원문 콘텐츠를 참고 자료로만 활용하며, 요청 시 원문 링크를 제공할 수 있지만 이는 원문을 복제·저장·재배포하거나 제3자에게 제공한다는 의미가 아니라고 명시한다. [썸트렌드 MCP 개인정보 처리방침](https://apps.some.co.kr/privacypolicy)
- 썸트렌드는 Social API 문의 양식과 서비스 문의 연락처를 공개한다. [Social API 문의](https://data.some.co.kr/voucher/inquiry), [서비스 문의](https://biz.some.co.kr/login/)

### Inferences

- TourAPI는 상권 리포트에 주변 관광지·공식 장소 설명을 보강할 수 있지만, 개별 카페 고객 리뷰 비교 기능의 데이터 원천으로는 맞지 않는다.
- 썸트렌드는 카페명·브랜드명 단위의 온라인 언급량·감성 흐름을 비교하는 보조 기능에는 적합할 수 있다. 그러나 동일 상호, 지점 구분, 광고성 블로그, 장소 ID 매핑 문제 때문에 ‘주변 동종 매장의 실제 방문 리뷰’로 표현하면 안 된다.
- 리뷰 원문 표시가 필수라면 썸트렌드 집계 API보다 식신·다이닝코드의 자체 리뷰 B2B 계약이 우선이다.

### Gaps

- 조사한 공공·관광 데이터에서 서울 카페의 장소별 사용자 리뷰 원문을 지속 제공하는 공식 API를 확인하지 못했다.
- 썸트렌드의 장소 ID별 커버리지, 키워드 동명이인 제거, 상업 서비스에서의 집계 결과 재표시·보관 조건과 가격은 별도 문의가 필요하다.

## 제휴 문의와 파일럿은 어떤 조건으로 진행해야 하는가?

### Takeaway

제휴 문의는 “API가 있나요?”가 아니라 **원천 권리와 제품 이용권을 검증하는 짧은 파일럿 요청**이어야 한다. 식신·다이닝코드에는 동일한 사양서를 보내 비교하고, 샘플에서 원천·삭제·표시 권리가 불명확하면 개발을 시작하지 않는다.

### Cited Findings

- 식신과 다이닝코드 약관 모두 회원 게시물의 제휴 활용 가능성을 명시하는 동시에 회원의 게시물 삭제 요구 또는 탈퇴 시 삭제를 인정한다. 따라서 공급 계약은 삭제·정정 반영 절차를 포함해야 한다. [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html), [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php)
- 식신은 맞춤 데이터 서비스 문의 양식을, 다이닝코드는 데이터 제휴 이메일을, 레드테이블은 공식 DaaS 이메일·전화번호를 공개한다. [식신 문의](https://alipay.siksinhot.com/aidata), [다이닝코드 문의](https://www.diningcode.com/profile.php?rid=eDOEEXwuxAez), [레드테이블 문의](https://www.bigdata-culture.kr/bigdata/user/data_market/agency/detail.do?id=redtable_org)

### Inferences

권장 문의 사양:

1. **파일럿 범위**: 서울 25개 자치구 카페 중 100~500개 매장, 최근 6~12개월.
2. **필수 필드**: 공급자 장소 ID, 상호, 도로명 주소, 위·경도, 업종, 리뷰 ID, 작성 시각, 평점, 리뷰 본문, 원천 구분, 삭제·수정 시각. 작성자 실명·계정 ID는 받지 않는 방향.
3. **주변 경쟁점 기능**: 선택 매장의 위·경도와 업종을 기준으로 반경 또는 최근접 N개 동종 매장을 반환할 수 있는지, 또는 장소 검색 API와 리뷰 API를 함께 제공할 수 있는지 확인.
4. **권리 확인**: 리뷰 원문을 서버에 저장·캐시할 권리, 감성·주제·요약 분석과 통계 생성 권리, 서비스 화면에 원문 일부와 파생 분석을 표시할 권리, 내부 LLM 처리 가능 여부, 결과의 상업적 이용 가능 여부를 계약서에 명시.
5. **원천 보증**: 공급자가 자체 서비스에서 직접 수집하고 재라이선스 권리를 가진 리뷰만 제공하며, 네이버·카카오·구글·블로그 등 제3자 콘텐츠는 각 원천별 서면 권리 증빙 없이는 제외.
6. **삭제·정정**: 리뷰 삭제·비공개·수정 이벤트 피드, 반영 SLA, 권리자 신고와 긴급 삭제 채널, 계약 종료 시 원문 파기와 파생 통계 보존 가능 범위.
7. **운영 조건**: 가격 산식, 최소 계약금, 호출량·속도 제한, 증분 갱신 주기, 장애 SLA, 샘플 데이터, 테스트 키, 장소 매칭 정확도, 중복·스팸 정책.
8. **출처표시**: 공급자 로고·링크·리뷰 작성일 표기, 원문 링크 의무, 인용 길이, 리뷰어 익명화 규칙.

제휴 문의문에 넣을 핵심 문장:

> 서울에서 첫 카페 창업을 준비하는 사용자가 선택한 한 매장과 주변 동종 매장의 리뷰를 비교 분석하는 서비스입니다. 귀사가 직접 수집하고 제3자 서비스에 재라이선스할 권리를 가진 리뷰만 필요합니다. 리뷰 원문 또는 계약상 허용된 요약·감성·주제 결과를 API로 받고, 저장·분석·화면 표시할 수 있는 B2B 라이선스와 삭제·정정 동기화를 포함한 파일럿 견적을 요청드립니다.

### Gaps

- 공개 문서만으로 최종 법률 적합성을 확정할 수 없으며, 실제 공급 계약과 데이터 샘플의 원천 필드를 법무 검토해야 한다.
- 공급자가 “수집 가능”만 답하고 원천별 재라이선스 권리·삭제 동기화·파생분석 권리를 서면으로 보장하지 않으면 후보에서 제외해야 한다.

## 조사 결론과 실행 순서는 무엇인가?

### Takeaway

가장 현실적인 경로는 **식신과 다이닝코드에 동시에 동일 파일럿 사양을 보내고, 레드테이블에는 리뷰 원문 상품 존재 여부만 먼저 확인하는 것**이다. 네이버·카카오 공개 API는 장소 후보 탐색·좌표 매칭에만 사용하고 리뷰 수집에는 사용하지 않는다. 공공 관광 데이터와 썸트렌드는 필요할 때 보조 지표로만 검토한다.

### Cited Findings

- 식신은 공식 맞춤 데이터 서비스와 리뷰 제휴 활용 근거를 함께 공개한다. [식신 AI 데이터 서비스](https://alipay.siksinhot.com/aidata), [식신 이용약관](https://www.siksinhot.com/static2/html/siksinhot/service.html)
- 다이닝코드는 데이터 제휴 연락처, Open API 정의, 제휴 제3자에 대한 리뷰 활용 근거를 공개한다. [다이닝코드 문의](https://www.diningcode.com/profile.php?rid=eDOEEXwuxAez), [다이닝코드 이용약관](https://www.diningcode.com/policy.service.php)
- 네이버와 카카오의 공개 장소 API 응답에는 리뷰 원문 필드가 없다. [네이버 지역 검색 API](https://developers.naver.com/docs/serviceapi/search/local/local.md), [카카오 로컬 API](https://developers.kakao.com/docs/ko/local/dev-guide)

### Inferences

실행 순서:

1. 식신 문의 양식과 다이닝코드 `contact@diningcode.com`에 동일한 파일럿 요청서 발송.
2. 레드테이블 `bigdata@redtable.kr`에 자체 사용자 리뷰 원문 상품과 재라이선스 권리 보유 여부를 먼저 질문.
3. 답변을 `원천 권리 / 서울 카페 커버리지 / 원문·파생 권리 / 삭제 동기화 / 가격 / 기술 방식` 표로 비교.
4. 원천 권리 확인을 통과한 후보에게만 100~500개 매장 샘플과 테스트 계약 요청.
5. 샘플로 장소 매칭률, 최근 리뷰 비율, 매장별 리뷰 중앙값, 중복률, 삭제 이벤트를 검증한 뒤 공급자를 선정.
6. 계약 전에는 CSV 업로드 방식만 유지하고, 비공개 엔드포인트·브라우저 자동수집·스크레이퍼 상품은 사용하지 않음.

### Gaps

- 실제 제휴 문의 발송과 계약 협상은 아직 진행하지 않았다.
- 최종 공급자 선정은 회신 받은 권리 문서, 샘플 품질, 가격을 비교한 뒤 결정해야 한다.
