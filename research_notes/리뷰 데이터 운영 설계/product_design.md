# 리뷰 데이터 제품 설계

## 두 활용 맥락과 사용자 흐름

### Takeaway
리뷰 기능은 `상권 탐색용 집계`와 `개점 후 내 매장 운영 점검`을 하나의 권한·수집 파이프라인으로 쓰되, 화면의 질문과 비교 단위를 분리하는 편이 안전하다. 전자는 선택 상권 안의 동종 업종 고객 언급을 집계해 관찰 가능한 수요 신호를 보여 주고, 후자는 사용자가 권한을 가진 자기 매장과 같은 조건의 비교군을 통해 변화 추이를 점검한다. 둘 다 추천·성공 예측·평점 순위를 만들지 않는다.

### Cited Findings
- 프로젝트 Phase 17은 분석·재사용 권한이 확인된 데이터만 수집·분석하고, 권한이 없으면 공개 화면을 `준비 중`으로 두도록 정한다. [프로젝트 계획](../../docs/plan.md)
- 프로젝트는 결측·미제공 값을 0으로 바꾸지 않고 비교 불가와 사유를 반환하며, 모든 수치의 출처·기간·필터·계산식을 확인할 수 있어야 한다. [프로젝트 규칙](../../AGENTS.md)

### Inferences
- **상권 탐색:** 지도에서 공식 상권을 선택 → 업종(초기 카페)·기간을 고름 → 허가된 리뷰가 있는 가게만 묶어 `자주 언급된 주제`, `긍정/개선 요청 언급 비율`, `표본 가게 수·리뷰 수·기간·출처`를 표시한다. 개별 경쟁점의 순위·원문·정확한 이름은 기본 화면에서 노출하지 않는다.
- **운영 점검:** 사용자가 자신의 가게를 연결하거나 권한 있는 내보내기 파일을 제공 → 같은 공식 상권(우선)·같은 업종·최근 리뷰량이 비슷한 비교군을 정함 → 내 가게의 기간별 주제 변화와 비교군 분포를 나란히 보여 준다. 비교군은 `비교 가게 A/B/C`로 가명 처리하고, 세 곳 미만이면 개별 가명 카드 대신 그룹 중앙값/범위만 표시한다.
- 비교군 선정은 지리 반경 대신 공식 `trade_area_code`를 우선 키로 사용한다. 같은 상권에 표본이 부족할 때만 인접 공식 상권을 사용하되, 확장 여부와 목록 기준을 화면·근거에 명시하고 사용자가 해제할 수 있게 한다.
- 유사성은 `동일 업종 → 동일 공식 상권 → 리뷰 기간 겹침 → 리뷰 수 규모 → 가격대/서비스 유형` 순으로 필터링한다. 가격대·서비스 유형이 권한 있는 원천에 없다면 추정하지 않고 필터에서 제외한다.

### Gaps
- 어떤 공급자가 장소 카테고리·가격대·매장 소유자 검증을 제공하는지와, 개별 원문·AI 분석·파생 집계의 허용 범위는 제공자 계약/API 검토가 끝나야 확정할 수 있다.

## 표본 기준, 갱신 주기와 부족 데이터 처리

### Takeaway
처음에는 신뢰도를 과장하지 않는 보수적 임계값과 월간 갱신을 권장한다. 충분한 표본이 쌓이기 전에는 가게별 비교를 숨기고 상권 집계 또는 데이터 부족 안내만 제공한다.

### Cited Findings
- Phase 17 계획은 제공자·원문 식별자/링크·수집 시각·허가 근거·보관 만료를 기록하고, 표본 부족·권한 만료·수집 실패를 0으로 바꾸지 않도록 요구한다. [프로젝트 계획](../../docs/plan.md)

### Inferences
- **기본 기간:** 상권 탐색은 최근 12개월을 기본 창으로 하되 최근 90일과 91~365일을 함께 표시한다. 개점 후 운영은 최근 90일을 기본 창으로 하고 직전 90일 및 최근 12개월 추세와 비교한다. 계절성이 큰 카페는 12개월 누적을 보조값으로 유지한다.
- **수집 주기:** 기본은 30일마다 증분 수집(새 리뷰만). 내 가게는 권한과 API 한도가 허용하면 주 1회 증분 수집을 선택할 수 있으나, 화면 집계는 주 단위가 아닌 월 단위로 확정한다. 삭제·수정 동기화와 제공자 TTL은 계약 규칙이 우선한다.
- **가게별 표시 최소치(초기 권장):** 분석 기간 내 텍스트 리뷰 20건 이상, 최근 90일 텍스트 리뷰 5건 이상. 별점만 있는 리뷰는 주제 분석 표본에는 넣지 않고, 허용될 때 별도 건수로만 표시한다.
- **상권 집계 최소치(초기 권장):** 조건을 만족한 가게 5곳 이상 **그리고** 텍스트 리뷰 총 100건 이상. 운영 비교군은 적격 비교 가게 3곳 이상, 그룹 텍스트 리뷰 60건 이상이어야 분포를 표시한다. 이는 통계적 유의성 선언이 아니라 노이즈가 큰 소수 리뷰의 단정적 해석을 피하기 위한 제품 안전선이다.
- **부족 데이터 UX:** `비교 불가 — 최근 12개월 적격 가게 3곳/총 46건으로 최소 기준(5곳/100건)에 못 미칩니다`처럼 실제 분자·분모·기간·제외 사유를 표시한다. 대체로 (a) 기간을 24개월까지 넓혀 다시 보기, (b) 인접 공식 상권 포함, (c) 내 가게 리뷰만 추세 보기 중 사용자가 직접 고르게 한다. 어느 대체도 자동 적용하지 않는다.
- **익명성:** 적격 가게가 5곳 미만이면 A/B/C 가명도 역식별될 수 있으므로 개별 가명 카드·정렬·정확한 리뷰 수는 숨기고 그룹 집계만 노출한다. 5곳 이상일 때도 원문 인용·지도 핀·정확한 가게명·고유한 조합의 속성은 제공하지 않는다.

### Gaps
- 위 숫자는 초기 제품 정책 제안이다. 실제 제공자 데이터의 리뷰 분포, 텍스트 비율, 계약상 최소 집계 단위 및 개인정보 재식별 위험 검토 뒤 조정해야 한다.

## 구현 단계, 데이터 계약과 검증

### Takeaway
권한을 먼저 고정하고, 단일 제공자·소규모 파일럿·집계 전용 화면 순서로 공개해야 한다. 크롤러를 먼저 만들거나 권한 확인 전 실리뷰를 저장하는 계획은 Phase 17의 완료 조건과 맞지 않는다.

### Cited Findings
- 현재 프로젝트 문서는 Google Maps 크롤링·DB 적재·AI 분석 자동화를 금지하고, 네이버·카카오도 공개 리뷰 API 또는 서면 허가 전에는 크롤링하지 않는다고 명시한다. [프로젝트 계획](../../docs/plan.md)
- 현재 공급자 문의는 실제 답변 대기 상태이며, 서면 권한 확인 전에는 실데이터 adapter를 연결하지 않도록 기록돼 있다. [문의 현황](../../docs/review_provider_outreach.md)

### Inferences
- **0단계: 정책 결정표(선행):** 공급자별 허용 목적(내 매장/경쟁점/상권 집계), 원문 저장 여부, AI 처리, 화면 표시, attribution, TTL, 삭제·수정 동기화, 호출 한도, 한국 내 처리·재위탁을 계약서/API 약관 원문으로 승인한다. 승인 없으면 fixture만 사용한다.
- **1단계: 권한 있는 파일럿:** 단일 공급자 또는 매장 소유자 제공 내보내기, 10개 이하 매장, 카페 한 업종으로 시작한다. 원문 저장이 허용되지 않으면 텍스트를 저장하지 않고 승인된 분석 결과/집계만 보관한다.
- **2단계: 수집·정규화:** `review_provider`, `provider_place_id`, `provider_review_id`, `business_id`, `trade_area_code`, `industry_code`, `published_at`, `rating`, `text_or_tokenized_payload`, `source_url`, `license_basis_id`, `fetched_at`, `updated_at`, `expires_at`, `deleted_at`, `content_hash`를 둔다. 논리 중복 키는 `(provider, provider_review_id)`이며, 원문과 파생값 모두 보관 만료·삭제 요청을 전파한다.
- **3단계: 분석 계약:** 리뷰별 분석 결과에는 `topic_key`, `sentiment_label`, `model_version`, `prompt_version`, `analysed_at`, `confidence/unknown`, `exclusion_reason`을 보관한다. 집계에는 `window_start/end`, `eligible_business_count`, `eligible_review_count`, `excluded_review_count`, `aggregation_rule_version`, `data_status`, `reason`을 둔다. 모델은 긍정/부정의 사실 판정이 아니라 언급 분류 보조로 취급하며, 불확실하면 `unknown`으로 남긴다.
- **4단계: 두 화면 공개:** 먼저 상권 집계(개별 가게 미노출) → 충분한 k-익명 기준과 계약이 충족될 때만 운영 비교군 가명 카드 → 이후 사용자 피드백으로 주제 사전·문구를 보정한다.
- **완료 조건:** 각 카드에서 공급자, 라이선스 근거, 수집·갱신 시각, 분석 기간, 적격/제외 건수, 최소 기준, 보관 상태, 계산·모델 버전을 확인할 수 있다. 권한 미확인·만료·부분 실패는 `준비 중` 또는 `비교 불가`로 표시한다.
- **테스트:** adapter의 권한 차단·페이지네이션·rate limit·중복·수정·삭제·TTL, 장소/업종/상권 매칭 오류, 20/100/3/5 경계값, 익명성 억제, 기간 확장 동의, 결측 사유, 그룹 산식, 모델 버전 재현성, 계정 A/B 격리, PC·360px를 자동/수동으로 검증한다. fixture에는 실가게명·작성자 식별자를 넣지 않는다.

### Gaps
- 우선 연결할 제공자와 실제 계약 권한, 사용자 본인 매장 소유 확인 방식, 인접 상권의 공식 정의, 주제 분류 체계(예: 맛·가격·친절·대기·공간), 개인정보 처리방침/동의 문구, 데이터 보관 기간은 제품 결정이 필요하다.
- Phase 17을 시작하기 전에 필요한 공급자 키·계약·환경 변수와 실제 데이터 원천이 없으므로, 현재 즉시 구현 가능한 범위는 가짜 데이터 fixture와 권한 게이트·데이터 계약까지다.
