# 네이버·카카오 리뷰 데이터의 허용 경로

## 공식 리뷰 API·크롤링 허용 여부

### Takeaway
2026-11-04에 공개된 공식 개발자 문서 기준으로 네이버·카카오 모두 제3자가 장소 리뷰 본문·별점·작성일을 받는 공개 리뷰 API를 확인하지 못했다. 네이버는 명시적으로 승인되지 않은 자동 수집을 금지하므로, 네이버 지도/플레이스 리뷰 크롤링은 구현 경로에서 제외해야 한다. 카카오는 공식 로컬 API의 공개 기능 목록에 장소 검색만 있고 리뷰 응답이 없으므로, 지도 웹페이지·비공개 엔드포인트의 자동 수집을 허용된 API로 간주할 근거가 없다.

### Cited Findings
- 네이버의 서비스 접근 정책은 명시적 허용·사전 승낙, 적법한 클라이언트 ID로 제공 API 약관을 준수하는 경우, 개발자 가이드·robots.txt 허용 범위를 제외한 자동화 수단(크롤러·스크래퍼 등)의 서비스/API 접속 및 정보 수집을 금지한다. [네이버 서비스 접근 및 이용 정책](https://policy.naver.com/policy/disclaimer.html)
- 네이버 오픈 API 목록에는 검색·로그인·데이터랩·캡차·캘린더·카페·공유만 열거되어 있고 장소 리뷰 API는 열거되어 있지 않다. [네이버 오픈 API 목록](https://developers.naver.com/products/intro/plan/plan.md)
- 네이버 검색 API의 지역 검색은 지역 서비스에 등록된 업체·상호 검색결과를 제공하는 기능으로 소개되며, 리뷰를 제공한다고 명시하지 않는다. [네이버 검색 API 소개](https://developers.naver.com/products/service-api/search/search.md)
- 카카오맵 공식 문서는 REST API의 장소 검색 기능을 키워드·카테고리 기반 장소 검색으로 열거하고, 장소·주소·좌표·경로 조회를 제공한다고 설명한다. 리뷰 조회는 목록에 없다. [카카오맵 이해하기](https://developers.kakao.com/docs/ko/kakaomap/common)
- 카카오 로컬 API의 카테고리 장소 검색 응답 필드는 장소 ID·상호·카테고리·주소·좌표·상세 URL·거리이며 리뷰 텍스트·별점·작성일 필드는 명세에 없다. [카카오 로컬 API](https://developers.kakao.com/docs/ko/local/dev-guide)
- 카카오 REST API의 카카오맵 API 목록은 주소/좌표 변환, 장소 검색, 경로 조회만 열거한다. [카카오 REST API 레퍼런스](https://developers.kakao.com/docs/ko/rest-api/reference)

### Inferences
- 공개 문서에 없는 리뷰 엔드포인트를 브라우저 자동화, 화면 HTML 파싱, 내부 API 호출로 수집하는 것은 공개 API 사용이 아니며, 허가 근거가 확인될 때까지 채택하면 안 된다.
- 경쟁점 이름을 A/B/C로 바꾸는 것은 표시 방식일 뿐 수집·저장·분석의 권한을 만들지 않는다. 리뷰 원문이나 파생 주제·집계의 이용 범위는 원 제공자의 계약/서면 허가에서 별도로 받아야 한다.

### Gaps
- 카카오 일반 서비스 약관·카카오맵 개별 이용정책의 자동수집 조항은 이번 조사에서 신뢰성 있게 읽을 수 있는 공식 원문을 확보하지 못했다. 따라서 카카오 크롤링이 '허용'이라는 결론은 낼 수 없다.
- 네이버·카카오가 비공개 B2B 리뷰 데이터 계약을 제공하는지, 제공한다면 저장·AI 분석·익명 집계·삭제 동기화 조건이 무엇인지는 공개 개발자 문서만으로 확인할 수 없다.

## 안전한 대체 수집·분석 경로

### Takeaway
현재 즉시 구현 가능한 자동 경로는 리뷰가 아니라 공식 장소 검색을 통한 후보 장소 식별뿐이다. 리뷰 분석은 (1) 플랫폼 또는 데이터 제공자의 서면 계약/API가 분석·저장·표시를 명시적으로 허용하거나, (2) 자신의 가게에 대해 소유자/관리자가 적법하게 받은 내보내기 파일을 직접 업로드하는 경우로 제한하는 것이 안전하다.

### Cited Findings
- 카카오의 공식 카테고리 장소 검색은 카페(`CE7`) 등 미리 정의된 카테고리, 중심 좌표, 반경(0~20km), 거리순 정렬을 지원하며 장소 기본 정보를 반환한다. [카카오 로컬 API](https://developers.kakao.com/docs/ko/local/dev-guide)
- 네이버 검색 API 약관은 검색 API 데이터를 애플리케이션에서 네이버 검색결과로 제공하는 목적에만 사용하고, 원본 출처 표시 및 원본 이동 링크를 제공하며, 제공 목적에 맞지 않게 쓰지 않아야 한다고 규정한다. [NAVER API 서비스 이용약관](https://developers.naver.com/products/terms/)
- 카카오맵 API는 장소 검색에 REST API 키를 사용하며, 유료 사용·쿼터 정책을 별도로 둔다. [카카오맵 이해하기](https://developers.kakao.com/docs/ko/kakaomap/common), [카카오 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota)

### Inferences
- 카카오 장소 API는 경쟁 후보군을 찾는 보조 수단으로만 사용하고, 반환된 상호를 그대로 UI에 노출하는지·저장하는지의 이용 조건은 해당 API 약관을 출시 직전 재검토해야 한다. 리뷰 분석 입력으로 전환하면 안 된다.
- 소유자 제공 파일은 '자기 가게' 분석에 적합하지만 경쟁점 데이터를 자동으로 확보하는 해법은 아니다. 경쟁점 비교는 승인 제공자 계약이 생길 때까지 표본/분석 결과를 만들지 않고 `데이터 제공 준비 중`으로 표시한다.
- 계약 데이터 파일럿의 최소 계약 항목은 공급자·장소 ID·리뷰 ID·수집시각·보관기간·AI 분석/파생집계/익명표시/삭제요청·원문링크 및 저작자 표시 조건이다. 이는 해당 권리가 계약서에 명시될 때만 활성화한다.

### Gaps
- 리뷰 제공 계약을 맺기 전에는 '주변 상권의 같은 업종 리뷰 분석'을 자동으로 구현할 합법성·데이터 품질이 검증된 공개 데이터 경로를 찾지 못했다.
- 사용자 업로드 파일의 정확한 제공 방식과 재이용 권한은 플랫폼별 소유자 도구 약관 및 사용자가 가진 권한을 개별 검토해야 한다.

## 제품 표시·보안에 주는 결론

### Takeaway
출시 전에는 리뷰 기반 상권 분석과 경쟁점 비교를 기능적으로 분리해야 한다. `내 가게`는 권한이 확인된 파일/계약 데이터가 있을 때만 분석하고, `주변 비교`는 최소 표본·기간·출처·권한 상태가 모두 충족될 때만 익명 집계로 표시한다. 그 외에는 0이나 임의 인사이트 대신 사유가 있는 비활성 상태를 보여야 한다.

### Cited Findings
- 네이버는 자동수단으로 게시물·ID·검색·클릭 등을 수집하는 행위를 사전 허가 없이 하지 말아야 하며, 기술적 차단 우회도 금지한다고 안내한다. [네이버 이용약관](https://policy.naver.com/policy/service_en.html)
- 카카오 공식 장소 검색 응답은 `place_name`·`place_url` 등 개별 장소 식별 정보를 포함한다. [카카오 로컬 API](https://developers.kakao.com/docs/ko/local/dev-guide)

### Inferences
- 익명화는 다음 순서로 적용한다: 서버 내부의 승인된 `provider_place_id`로 중복을 관리 → 비교용 cohort를 산출 → 화면에서는 매 실행마다 안정적이지 않은 A/B/C 별칭 또는 집계값만 노출한다. 단, 계약이 장소명·원문링크 표시를 요구할 수 있으므로 계약 조건이 우선한다.
- 실제 사용 전 차단 조건은 `권한 근거 없음`, `보관 만료`, `삭제 동기화 미확인`, `표본 기준 미달`, `기간 데이터 부족`, `분석 실패`로 분리한다. 모두 결과값 0으로 대체하지 않는다.

### Gaps
- 익명화한 파생 지표의 재배포 가능 여부는 각 공급자 계약 조항에 좌우되며, 공개 정책만으로 일반화할 수 없다.
