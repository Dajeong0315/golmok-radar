### 2026-11-10 품질 검사 결과 (Phase 39)

`database/scripts/data_quality.py --quarter 20254`로 위 원천을 검사했습니다. 점포 75,985행·매출 21,333행·영역 1,650곳에서 위반은 0건이고, 표본 12건의 손계산이 백엔드 계산과 일치했습니다. 유동인구 원천은 이 환경에 없어 `missing_source` 오류로 보고됩니다.

- 매출: 모든 행에서 `주중_매출_금액 + 주말_매출_금액 = 당월_매출_금액`, `시간대_00~06 … 21~24_매출_금액`의 합 = `당월_매출_금액`.
- 점포: `opbiz_rt`·`clsbiz_rt`는 `opbiz_stor_co`·`clsbiz_stor_co ÷ similr_induty_stor_co × 100`을 정수로 나타낸 값이며 100%를 넘을 수 있습니다(20254 폐업률 40건·개업률 4건). 105건은 단순 반올림과 1포인트 이내로 다릅니다.
- 유동인구: Open API 샘플에서 `TMZON_*_FLPOP_CO` 합계와 `TOT_FLPOP_CO`가 ±1 다릅니다.

## 8. V2 리뷰 데이터 계약

### Phase 32 업종별·상권별 표본 확장 (2026-11-05)

- 공식 점포 업종 코드 100개는 카카오 장소 분류 코드와 동일하지 않습니다. `/api/v1/review-industry/{code}`가 업종명에서 보수적으로 도출한 카카오 분류 검색어·제외어를 반환합니다. 결과의 장소 분류가 일치하지 않으면 비교군에 넣지 않습니다. 카카오의 [장소 검색 REST API](https://developers.kakao.com/docs/ko/local/dev-guide)는 장소 ID·분류·좌표를 반환하며, 서버는 수집 직전 REST API 키로 이를 재조회해 클라이언트 선택값을 검증합니다. 이는 두 데이터 체계의 통계적 동등성을 뜻하지 않습니다.
- 개업 후 경로: 내 가게의 위치를 지도에서 확인하고 선택한 업종의 장소 분류를 검증한 뒤, 같은 공식 상권을 우선하는 반경 1.2km 동종 후보 최대 9곳을 A~I로 비교합니다. 키가 없거나 내 가게의 분류가 맞지 않으면 수집을 시작하지 않고 사유를 반환합니다.
- 창업 전 경로: 사용자가 공식 상권과 업종을 고르면 해당 상권 경계 **안**의 동종 장소 최대 10곳을 A~J로 수집하고, 가게별 표본 수와 상권 집계 주제만 표시합니다. 특정 가게의 상호·리뷰 원문·개별 성과는 반환하지 않습니다. Phase 35부터 분석 요청마다 새 표본을 수집합니다.
- 두 경로 모두 요청당 최대 10곳·가게당 공개 화면에 나타난 텍스트 리뷰 최대 40건을 수집하고, 암호문은 최대 90일 보관합니다. 새 수집에 성공하면 같은 대상의 이전 암호문을 교체합니다. Phase 34부터 공개 텍스트 리뷰가 1건 이상이면 관찰된 표본의 주제를 탐색용으로 집계합니다. 가게별 5건·3곳·30건은 충분한 표본 기준이며, 5곳·50건부터 전체 표본입니다. 0건이면 주제를 만들지 않고 수집 상태를 보여줍니다. 수집 실패와 표본 부족을 구분합니다.
- 주제 어휘는 음식업, 서비스업, 소매업으로 구분합니다. 단순 단어 포함 집계이므로 고객 전체의 의견이나 매출 원인을 추론하지 않습니다. 카카오 장소 검색 결과의 누락이나 분류 오차 때문에 동종 가게가 3곳 미만으로 확인될 수 있습니다.

2026년 11월 5일 로그인 계정의 상권 선택 실사용 검증에서 공식 상권 `3110135`·업종 `CS100010`의 동종 가게 4곳(A~D)을 수집했습니다. 가게별 10·2·5·2건, 전체 19건 중 가게당 5건 기준을 통과한 A·C의 15건만 분석 대상으로 집계했습니다. 적격 가게 2곳으로 최소 3곳·30건에 미달해 화면은 `표본 부족`과 추가 필요량 1곳·15건을 표시하고 주제 집계는 만들지 않았습니다. Phase 34 재분석에서는 위 카페 보관본 19건과 같은 상권의 여관 보관본 15건이 각각 `limited` 탐색용 보고서로 변환됩니다. 여관 보관본은 5곳의 15건이며, 현재 공개 장소 페이지 1곳을 확인했을 때 HTTP 200과 기존 선택자에 걸리는 텍스트 리뷰 3건이 확인됐습니다. 이 사례의 기존 0건 화면은 후보 3곳 미만일 때 수집 전에 중단하는 분기와 구분해야 합니다. 2개 보관본만으로 전체 요청의 99% 생성률을 추정할 수 없습니다.

Phase 35 수집기 실측(2026-11-05): 카카오 공개 장소 검색에서 반경 1.2km 이내 카페 10곳을 골라 공개 페이지를 순차 방문한 결과 텍스트 리뷰 72건, 장소별 실제 최대 20건, 페이지 실패 0곳이었습니다. 이는 수집기 상한 10곳×40건의 동작 확인이며 10곳이 한 공식 상권 안에 있다는 검증이나 사용자 보고서 생성률 측정은 아닙니다. 이 검증에서는 리뷰 원문·장소명을 출력하거나 영구 저장하지 않았습니다.

2026-11-08 로그인 QA에서는 내 가게 비교 두 번이 각각 10곳·77건, 카페 상권 분석 두 번이 각각 4곳·20건, 세탁소 상권 분석 한 번이 1곳·4건으로 수집됐습니다. 서버 감사 기록의 신규 `capture` 5건과 각 장소·리뷰·실패 건수(모두 실패 0건)가 일치합니다. 동물병원은 검증 장소가 0곳이라 수집·감사 기록이 없고, 기타법무서비스는 카카오 검색 후보가 0곳이라 서버 요청 전 중단됐습니다. 이 자료는 요청 전체의 99% 생성률이나 실제 일부 장소 수집 실패 시 화면을 검증하지 않습니다.

Phase 36 완료 시점에는 새 형식의 실사용 결과가 0건이었습니다. 후보 0곳으로 프론트엔드에서 멈춘 시도, 잘못된 요청, 서버 오류는 이 분모 밖이며 전체 사용자 시도의 생성률은 별도 계측이 필요합니다. 부분 실패는 강제 재현 자동 테스트로 확인했고, 실제 카카오 장소가 일부 실패하는 실사용 사례는 아직 관측되지 않았습니다.

Phase 37 QA 이후 백엔드를 재시작하여 새 형식의 실제 상권 분석 결과 2건을 확인했습니다. 각각 `capture`와 `analysis_result`가 같은 시각·가게 수·리뷰 수로 기록됐으며, 10곳·103건과 10곳·104건 모두 `available`, 실패 장소 0곳입니다. 집계 명령은 완료 2건·생성 2건을 반환합니다. 재시작 전 QA의 내 가게 비교 2건, 상권 수집 3건, 검증 가게 0곳 1건은 새 결과 감사 항목이 없어서 소급 계산하지 않습니다. 후보 0곳 1건은 서버 요청 전 종료됐습니다. 표본 2건의 100%는 전체 요청 생성률의 추정값으로 사용하지 않습니다.

카카오 장소 검색과 공식 상권 경계로 내 가게의 소속 또는 가장 가까운 상권을 판별합니다. 자동 비교는 같은 공식 상권의 동종 가게를 거리순으로 우선 고르고, 부족할 때 반경 1.2km의 인접 가게를 보충해 최대 9곳을 A~I로 표시합니다. 경계 밖 가게는 공식 상권 소속을 주장하지 않고 반경 비교만 제공합니다. 한 번에 내 가게를 포함해 최대 10곳·가게당 공개 화면에서 보이는 리뷰 최대 40건을 수집합니다. 요청마다 새로 수집하며 과거 집계 결과는 별도 계정 기록으로 보존합니다. 자동 흐름의 리뷰 출처는 카카오 공개 화면입니다. 네이버는 수동 파일럿만 시도했으며 [공식 지역 검색 API](https://api.ncloud-docs.com/docs/naver-api-hub-search-local)는 리뷰 본문을 제공하지 않습니다. 로그인·CAPTCHA·차단 우회와 비공개 엔드포인트 호출은 하지 않습니다.

- 비교 주제: 메뉴·맛, 가격, 응대, 대기, 청결, 공간·분위기
- 분석 방법: 공개된 키워드 포함 여부와 단순 긍·부정 어휘 수 비교

- 수동 입력 기준: 내 가게와 주변 비교군이 각각 5건 미만이면 집계만 표시하고 실행 아이디어는 숨김
- 내부 fixture 계약: `group`은 `own` 또는 `nearby`, `review`는 비식별 테스트 문구이며 각 그룹 최대 500건

Phase 19에서는 원천 파일이나 외부 데이터셋을 새로 수집하지 않습니다. 워크시트 값은 로그인 없는 MVP의 브라우저 localStorage에만 저장하며 서버·분석 DB·원천 보관 폴더로 전송하거나 적재하지 않습니다.

각 매물 기록에는 사용자 입력일과 마지막 수정일, 사용자가 식별할 수 있는 위치 설명, 면적 단위, 부가세 포함 여부 또는 확인 상태를 구분합니다. 서울시 상권 통계에는 출처·기준분기·상권 코드·업종 코드가, R-ONE 임대 벤치마크에는 제공기관·기준기간·조사상권 코드가, 사용자 입력 매물에는 `사용자 입력`·입력일·확인 상태가 표시되어 서로 혼동되지 않아야 합니다.

건축물 용도, 영업 가능 여부, 임대차 특약, 원상복구 등은 `확인 완료`, `추가 확인`, `해당 없음`, `기록 없음` 상태로만 기록합니다. 이는 계약 안전성·법률·세무·인허가의 판단이나 보증이 아니며, 공식 기관 또는 전문가 확인이 필요합니다. 실매물 자동 수집, 비공개 API 호출, 화면 크롤링, 로그인 우회, 주소 기반 자동 조회는 이 데이터 범위에 포함하지 않습니다.
